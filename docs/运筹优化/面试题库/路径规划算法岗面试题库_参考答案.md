# 路径规划算法岗面试题库：130 题参考答案

本页与[130 题题库](./路径规划算法岗面试题库.md)按新编号逐题对应，保留完整题干、考点、参考回答和高分要点。考点用于理解提问意图；项目题中的规模、效果和个人贡献必须用自己的真实记录作答。以下默认最小化问题；求解器接口与状态以所用版本的官方文档为准。路径时间窗默认要求开始服务时刻落在允许区间内，允许早到等待，除非题目另有约定。

## 一、业务与项目题

### 常规主问

#### 1. 两分钟介绍路径规划项目

**题目：** **[项目]** 用两分钟讲清你做的路径规划项目：业务目标、输入规模、约束、算法、结果和你本人负责的部分。

**考点：** 能否用真实数据说清个人贡献与项目结果

**参考回答：** “我处理的是 `[场景]`，有 `[客户数、车数、数据频率]`，目标按 `[车数、距离、迟到等顺序]` 优化；硬约束包括 `[容量、时间窗、司机班次]`。我负责 `[建模 / 数据 / 算法 / 验证]`，采用 `[方法]`，与 `[基线]` 在同一预算下比较，得到 `[真实指标]`。最大的难点是 `[具体问题]`，我通过 `[措施]` 解决。”

**高分要点：** 说清个人贡献、可行性验证、对照实验和一个失败案例；所有数字能追溯到实验记录。

#### 2. 接到末端配送需求先确认什么

**题目：** **[业务建模]** 面对一个末端配送需求，你会先向业务方确认哪些规则，再决定它是 TSP、CVRP、VRPTW 还是更复杂的变种？

**考点：** 能否先澄清业务规则再选择路径问题类型

**参考回答：** 先问客户是否必须服务、订单需求与取送关系、车队是否同质、仓库及终点、预约窗与服务时长、司机班次、交通时间、拒单或迟到规则、目标优先级、计划频率和求解时限。单车无资源限制是 TSP；多车有容量是 CVRP；再有时间窗是 VRPTW；取送货、多仓库、动态订单需扩展。

**高分要点：** 把业务语句翻成“目标、硬约束、软约束、数据字段”，并指出需要向业务方确认的歧义。

#### 3. 分级目标与加权目标

**题目：** **[目标函数]** “先最少车辆、再最短距离”与“距离加车辆固定成本”有何区别？怎样保证代码中的目标与业务优先级一致？

**考点：** 能否把目标优先级准确落到模型和代码

**参考回答：** 分级目标先求最少车数 $m^*$，再固定 $m=m^*$ 最小化距离；加权目标最小化 $F m+D$，只有 $F$ 大于所有可能的距离差等可证明界时，才与严格字典序等价。实际车辆固定成本若真是经济成本，则加权目标可能是正确业务定义。

**高分要点：** 说明业务偏好和模型目标分开确认；不要随意取“大概足够大”的权重。Solomon 常见基准采用先车数后距离的层级目标。[基准定义](https://www.sintef.no/projectweb/top/vrptw/solomon-benchmark/)

#### 4. 逐点计算 VRPTW 时间

**题目：** **[时间窗]** 给定一条路线，如何逐点计算到达、等待、开始服务和返回仓库的时间，并判断硬时间窗可行性？

**考点：** 能否正确递推到达、等待、服务和回仓时间

**参考回答：** 令 $B_i$ 是在 $i$ 开始服务时间，下一点到达 $A_j=B_i+s_i+\tau_{ij}$，开始服务 $B_j=\max(A_j,e_j)$，等待 $W_j=B_j-A_j$。检查 $B_j\le l_j$，并在最后检查返回仓库的截止时间及整条路线工作时长。沿路线同时累计需求和距离。

**高分要点：** 区分到达、开始服务和离开时间；明确仓库出发时间、早到等待和“最晚开始”还是“最晚完成”的业务定义。

#### 5. 距离与行驶时间为什么分开

**题目：** **[数据语义]** 距离矩阵和行驶时间矩阵为何要分开？服务时间、等待时间和车辆工作时长各进入哪些约束？

**考点：** 能否分清距离、行驶时间和司机工作时长

**参考回答：** 目标成本可按里程、油费或通行费计算；时间窗使用行驶时间，再加服务和等待。两点相同距离可能因路况、道路类型、方向和时段导致不同耗时。路线工作时长含行驶、服务、等待及可能的装卸休息，而非单纯距离。

**高分要点：** 说明单位、非对称和时变情况；不要在没有常速假设时用距离直接代替时间。

#### 6. 求解前的不可行性预检

**题目：** **[可行性]** 在调用求解器前，你会做哪些快速不可行性检查？这些检查为什么通常只是必要条件？

**考点：** 能否用必要条件提前发现明显不可行输入

**参考回答：** 检查 $d_i\le Q$、$\sum d_i\le KQ$（有限车数）、窗口顺序 $e_i\le l_i$、从仓库到每位客户并返回的最早可行时刻、司机班次覆盖及必要服务资格。若任何必要条件失败，则可直接判不可行；全通过也未必可行，因为客户间排序和共享车辆仍可能冲突。

**高分要点：** 区分必要与充分条件；给出单客户往返不可行、总需求可行却时间窗互斥的反例。

#### 7. 独立解验证器

**题目：** **[工程]** 如何写一个独立于求解器的解验证器，检查漏访、重复访问、超载、迟到、车辆数和回仓库？

**考点：** 能否独立校验路线的全部业务硬约束

**参考回答：** 输入实例和每辆车的客户序列；先用计数器检查每位必访客户恰好出现一次，再逐车从仓库重放，累计真实成本、载重、到达、等待、服务、回仓库与工时，最后检查车数和所有硬约束。验证器不读取算法内部缓存，返回结构化错误如“车 3 在客户 17 迟到 6 分钟”。

**高分要点：** 用独立计算避免同一 bug 在求解与验证中互相掩盖；覆盖空车、单客户和浮点容差。

#### 8. 上界、下界与 Gap

**题目：** **[结果解释]** 什么是可行解上界、松弛下界和 MIP Gap？何时可以说“找到最优解”？

**考点：** 能否解释上界、下界与最优性证明

**参考回答：** 最小化问题的可行整数解成本是上界 $UB$，有效松弛 / 分支证明给出下界 $LB\le OPT\le UB$。常见相对 Gap 为 $(UB-LB)/|UB|$，零目标值需另行处理。只有在给定数值容差和模型定义下 Gap 闭合，才可称已证明最优；“最好已知解”只是上界。

**高分要点：** 说明启发式只能给可行上界，时间到但有解不等于最优；求解器状态 `OPTIMAL` 也受设定容差约束。[Gurobi 日志说明](https://docs.gurobi.com/projects/optimizer/en/current/concepts/logging/mip.html)

#### 9. 不同规模与时限如何选方法

**题目：** **[方法选择]** 对 30、300、3000 个客户且分别要求证明最优或限时给出可行解的任务，你如何选择精确算法、启发式或混合方案？

**考点：** 能否依据规模、时限和证明要求选法

**参考回答：** 先看资源和窗口紧度，不只看节点数。小实例需证明时，用紧致 MIP 或分支切割；中等实例可尝试路线列生成、分支定价并用启发式给上界；数千点且秒级 / 分钟级响应时，通常按区域分解、构造加局部搜索或 ALNS，并明确没有最优性证明。所有方案都要通过同一验证器。

**高分要点：** 解释实时性、约束复杂度、质量要求和开发成本的取舍，不报固定“某算法最多解多少点”。

#### 10. 如何报告项目效果

**题目：** **[项目实验]** 你的项目改善了什么指标？实例、时间预算、随机种子、基线和硬件是否一致？如何避免夸大改进？

**考点：** 能否用公平基线和一致预算证明改进

**参考回答：** 用统一的实例、成本定义、时间预算、硬件和随机种子，与简单基线及公开可比结果比较；报告车数、总距离、可行率、平均 / 分位运行时间和多随机种子波动。把改善写成“相对于基线减少了多少”，若无最优下界就不写“距最优多少”。

**高分要点：** 结果可复现、包含失败实例、公开所有停止条件；区分均值、最佳值与单次幸运运行。

#### 11. 读 MIP 日志诊断瓶颈

**题目：** **[求解器日志]** 给你一段 MIP 日志，如何区分“迟迟找不到可行解”和“已有好解但下界不涨”？各自优先检查什么？

**考点：** 能否从 MIP 日志定位首解或下界瓶颈

**参考回答：** 看 `Incumbent` 是否存在 / 改善、`BestBd` 是否上升、Gap、根节点耗时、探索节点数。没有 incumbent 时先查实例可行性、构造初解、时间窗与 Big-M；已有好解但 `BestBd` 停滞时关注松弛强度、割、分支和对称性。也要排查回调或定价耗时。

**高分要点：** 给日志字段与相应行动的对应关系；不把“时间到还没解”误报为“模型不可行”。[Gurobi MIP 日志](https://docs.gurobi.com/projects/optimizer/en/current/concepts/logging/mip.html)

#### 12. Gurobi、OR-Tools Routing、自写 ALNS

**题目：** **[工具选择]** Gurobi MIP、OR-Tools Routing、自己写 ALNS 各适合什么任务？如何比较“找可行解”和“证明最优”的能力？

**考点：** 能否按照证明需求和规模选择工具

**参考回答：** Gurobi 适合自定义 MIP、割和可验证的上下界；OR-Tools Routing 提供成熟的路线 / 资源约束接口及搜索策略，适合快速得到可行高质量方案，但其 Routing 搜索通常不提供大型实例的全局最优证明；自写 ALNS 方便为特定业务设计算子，代价是验证与维护都由自己承担。

**高分要点：** 比较时统一目标和时限，不只比较一个目标数字；区分产品能力与当前模型 / 参数设置。[OR-Tools Routing 概览](https://developers.google.com/optimization/routing)

#### 13. 100 单、20 车的现场建模

**题目：** **[现场场景]** 给 100 个订单、20 辆车、配送时间窗和司机下班时间，你会如何定义目标、变量、硬约束、软约束及最初可运行的基线？

**考点：** 能否在新场景中提出可运行的目标与约束基线

**参考回答：** 先确认订单必达、迟到政策、司机是否能加班及车数目标。最小模型以客户覆盖、每车容量、服务窗、仓库往返和司机截止为硬约束，以车数 / 总成本按业务排序；若允许迟到则引入非负迟到变量及罚金。第一版用插入启发式 + 独立验证器给可行基线，小实例再建 MIP 核对，之后按瓶颈增设 ALNS 或分解。

**高分要点：** 将“20 辆可用”解释为至多 20 辆，并核对司机与车辆是否一一对应。

#### 14. 手写路线验证函数

**题目：** **[手写代码]** 写一个函数接收客户序列和实例数据，返回该路线的成本、完整时间表及第一个不可行原因；时间复杂度是多少？

**考点：** 能否写出可靠的路线评价与失败原因定位器

**参考回答：** 循环处理 `[0]+route+[0]` 的每条弧，累计成本；到客户时加需求、计算 `arrival=service_start_i+service_i+travel[i][j]`，再 `start=max(arrival,early[j])`，若超载 / 超窗立刻返回失败原因；到仓库检查返回截止。返回成本、每站 `(到达,等待,开始服务)` 和状态，单路线 $m$ 个客户时间 $O(m)$。

**高分要点：** 调用前检查 ID 合法、路线内不重复；整个方案的跨车重复 / 漏访交给 `Solution` 验证。

#### 15. 返回“无解”如何排查

**题目：** **[故障排查]** 算法返回“无解”时，你如何区分输入数据错误、模型写错、确实不可行和求解超时？

**考点：** 能否区分数据、模型与求解时限造成的无解

**参考回答：** 先看状态：`TIME_LIMIT` 只是未在预算内找到解；`INFEASIBLE` 才是对当前数学模型的不可行证明。再核对数据与单位，跑必要条件和独立单路线验证，逐组放松时间窗、容量等约束定位冲突，用 IIS / 冲突分析找最小冲突集，检查 Big-M 与索引错误。

**高分要点：** 区分真实业务无解和模型错误；不要直接放松承诺给客户的硬约束。[Gurobi 状态码](https://docs.gurobi.com/projects/optimizer/en/current/reference/numericcodes/statuscodes.html)

#### 16. 距离下降却更晚送达

**题目：** **[业务沟通]** 如果算法把总距离降低了 8%，却让一部分客户更晚收到货，你会怎样解释并重新定义评价指标？

**考点：** 能否识别距离改善与客户体验的冲突

**参考回答：** 先核实所有硬时窗都满足，再展示距离、车辆数、迟到 / 晚到分布、尾部客户等待和成本变化。若“更晚”损害业务，应定义服务时间指标，如超约概率、95 分位送达时刻或软迟到罚金，提供多种权衡方案让业务方确定优先级，而非只展示距离下降。

**高分要点：** 区分“仍在承诺窗内更晚”与“真正违反时窗”；用分层客户指标避免均值掩盖问题。

#### 17. 时间窗限制到达还是服务开始

**题目：** **[时间窗语义]** 时间窗限制的是到达时刻还是开始服务时刻？若在最晚时刻到达但服务跨窗，算不算可行？

**考点：** 能否确认时间窗约束的业务语义

**参考回答：** 必须先按业务合同定义。标准硬时间窗 VRPTW 常规定开始服务时刻 $B_i\in[e_i,l_i]$，允许早到等待；若 $B_i=l_i$ 且服务延续到窗外，在“最晚开始”定义下仍可行。若业务要求在窗内完成，则要检查 $B_i+s_i\le l_i$。

**高分要点：** 到达、开始、完成三者不要混写；同一规则贯穿数据、算法和验证器。

#### 18. 取送货约束

**题目：** **[取送货]** 若订单有取货点和送货点，怎样加入先取后送、同车服务和沿路载重变化？

**考点：** 能否保证取送先后、同车和动态载重

**参考回答：** 每个订单关联取货 $p$ 和送货 $d$，二者同车，且路线序列中 $p$ 必须先于 $d$；载重在取货时增加、送货时减少，并在每一步满足 $0\le q\le Q$。紧致模型可用先后变量 / 流约束；标签要记录已取未送订单；ALNS 移除和插入时以订单对为单位或做配对修复。

**高分要点：** 单看总需求不够，必须验证沿途载重曲线和先后关系。

#### 19. 软时间窗

**题目：** **[软时间窗]** 客户允许迟到并支付罚金时，模型与 ALNS 评价函数如何改？怎样避免把软约束误当硬约束？

**考点：** 能否区分硬时间窗与迟到罚金

**参考回答：** 若可迟到，定义 $z_i\ge B_i-l_i,\ z_i\ge0$，在目标加 $p_i z_i$ 或分段罚金；硬窗约束相应调整。ALNS 中用相同罚则评价候选，独立报告迟到数量、分钟数和总罚款。若仍有不可违反的最晚截止，应另保留硬上界。

**高分要点：** 罚金单位与距离 / 车辆成本一致；不能只删掉 $B_i\le l_i$ 而不记录服务损失。

#### 20. IIS 与冲突诊断

**题目：** **[不可行性诊断]** MIP 模型不可行时，IIS、冲突分析、逐层放松约束各能帮助你发现什么？

**考点：** 能否用冲突信息定位当前模型的矛盾

**参考回答：** IIS 是一组不可行约束 / 变量界，去掉其中任意一项后该组不再不可行，帮助定位冲突，但不保证唯一。先核数据、字段和单位，再计算 IIS；把冲突翻译成业务语句，例如“司机班次截止、客户窗口和必访同时无法满足”。逐层放松可用于定位，但不能把临时放松当最终方案。

**高分要点：** 说明 IIS 是对当前数学模型的诊断，不自动证明业务规则本身错误。

#### 21. Gurobi 求解状态与交付

**题目：** **[求解状态]** `OPTIMAL`、`TIME_LIMIT`、`INFEASIBLE`、`INF_OR_UNBD` 等状态下，怎样决定是否可以读取并交付一个路线解？

**考点：** 能否按状态与解数量安全交付路线

**参考回答：** `OPTIMAL` 表示按容差求到模型最优；`TIME_LIMIT` 只表示达到时限，可先检查 `SolCount>0` 再读取解；`INFEASIBLE` 是模型不可行证明，不能读路线；`INF_OR_UNBD` 需按文档关闭 `DualReductions` 后重求以区分。无论状态如何，准备交付的解都要用独立验证器检查。

**高分要点：** 绝不在 `SolCount=0` 时直接读取 `X/ObjVal`；报告终止状态、上界、下界和 Gap。[Gurobi 状态码](https://docs.gurobi.com/projects/optimizer/en/current/reference/numericcodes/statuscodes.html)、[模型属性](https://docs.gurobi.com/projects/optimizer/en/current/reference/attributes/model.html)

#### 22. 数值误差造成的业务不可行

**题目：** **[数值稳定]** Big-M 过大、浮点误差、距离舍入和容差设置可能怎样制造“模型可行但业务不可行”的结果？

**考点：** 能否识别数值容差和舍入引起的业务违约

**参考回答：** 过大的 Big-M 会令 LP 松弛很弱、系数尺度失衡；浮点容差可能允许小幅超窗 / 超载，过早舍入距离与时间可能把边界实例判错。建模时收紧量纲与 $M$，按基准规定使用精度，输出时用业务容差独立重算，而非简单按打印出来的小数判断。

**高分要点：** 区分整数容差、约束可行容差与业务硬截止；例如“迟到 0.00001 分钟”如何处理要明确。

#### 23. 求解器 Gap 与 BKS 改进率

**题目：** **[Gap 计算]** 求解器报告的相对 Gap 与业务希望看到的“相对最好已知解改进率”有何区别？

**考点：** 能否区分证明差距与基准改进率

**参考回答：** 求解器 Gap 比较同一模型当前可行上界与有效下界，反映尚未证明的最优性空间；相对最好已知解（BKS）的改进率只比较两个可行上界，不提供最优性证明。两者的分母、目标定义和数值规则都必须注明。

**高分要点：** 最小化时可分别写 $(UB-LB)/|UB|$ 与 $(BKS-UB)/BKS$（分母非零时）；不能把 BKS 当理论下界。

#### 24. 出车后新增订单

**题目：** **[动态订单]** 新订单在车辆已出发后到达，你会怎样做局部插入或滚动重优化，并保留已承诺的服务？

**考点：** 能否在滚动重算中保留已承诺服务

**参考回答：** 固定车辆已走过的路线前缀与已承诺时窗，仅优化未执行后缀；先尝试可行的最小增量插入，再在滚动时域内重排有限邻域。目标加入改计划成本 / 稳定性，防止每分钟给司机完全不同的路线。

**高分要点：** 以当前车辆位置、时间和真实载重作为新起点；订单承诺与已通知客户的规则不可随意改。

#### 25. 不确定行驶时间如何选方法

**题目：** **[不确定性]** 行驶时间不稳定时，你会选安全裕度、鲁棒优化、情景优化还是仿真评估？选择依据是什么？

**考点：** 能否按风险要求选择不确定性处理方式

**参考回答：** 若数据少且需快速上线，用历史分位数安全裕度并仿真校验；有可信分布和服务水平约束，可用情景 / 机会约束；只知区间且需最坏情形保障，可用鲁棒优化。方法要按迟到代价、风险承受能力、数据量和计算预算选择。

**高分要点：** 明确“按均值可行”不等于“高概率准时”，并报告成本与准时率的权衡。

#### 26. 业务成本如何校准

**题目：** **[成本校准]** 业务提供油费、人工、违约金和车辆固定成本，你怎样把它们转换成一致单位且可解释的目标？

**高分要点：** 避免同一项重复计费，比如距离费已含油费又另加油费。

#### 27. 批量与实时规划

**题目：** **[线上系统]** 每天批量重算与实时滚动规划的延迟、稳定性和可解释性要求有何不同？

**考点：** 能否权衡批量与实时规划的系统要求

**高分要点：** 除优化目标外说明系统 SLA、可解释性、重规划频率和司机端发布机制。

#### 28. 数据质量门禁

**题目：** **[数据质量]** 订单缺坐标、时间窗颠倒、需求为负、重复 ID 时，数据管线应怎样拒绝或修复输入？

#### 30. 审查陌生 VRPTW 模型

**题目：** **[模型审查]** 给你一份陌生 VRPTW 数学模型，如何检查仓库起终点、客户恰好服务一次、Big-M 激活方向和时间循环漏洞？

#### 31. 新业务的最小可运行模型

**题目：** **[临场建模]** 一项新业务同时有预约时间、司机技能、订单优先级和部分可拒订单，你会先给出什么最小可运行模型，再逐步加哪些限制？

**高分要点：** 先建可验证的正确基线，再加复杂性；问清缺失数据和冲突规则，而不是默认所有订单都可达。

#### 32. 缺少服务时长或违约成本

**题目：** **[缺失参数]** 业务拿不出准确服务时长或违约成本时，你会怎样估计、做敏感性分析并向业务说明决策风险？

#### 33. 运营与客服目标冲突

**题目：** **[跨团队沟通]** 运营希望更少车辆，客服希望更少迟到，算法算出两者不能兼得时，你如何给出可选择的权衡方案？

#### 34. 上线试点效果不及离线

**题目：** **[复盘]** 一个上线试点没达到离线算例效果，你会怎样从数据、目标、求解时间、系统接入和实际执行逐层复盘？

#### 36. 项目对象职责

**题目：** **[项目架构]** 你的 `ProblemData`、`Route`、`Solution` 和搜索器分别负责什么？哪些状态必须在每次移动后更新？

**参考回答：** `ProblemData` 保存不可变输入和矩阵；`Route` 保存访问序列及可重算 / 缓存的载重、时间表、距离；`Solution` 管理路线集合、客户覆盖和总目标；搜索器负责算子、接受规则及停止条件。移动一个客户后，更新两条受影响路线的序列、成本、载重和时间缓存，最后由独立验证器复核。

#### 37. 读取 Solomon C101 / C102

**高分要点：** 别把表格展示的两位小数提前用于计算；对照 Solomon 基准的先车数、后距离目标。[SINTEF 基准说明](https://www.sintef.no/projectweb/top/vrptw/solomon-benchmark/)

#### 38. ALNS 停滞时的诊断

**题目：** **[搜索诊断]** ALNS 长时间没有改进时，你会区分“破坏力度不够”“修复过于贪婪”“接受率过低”还是“初始解太差”？

**考点：** 能否用日志定位 ALNS 停滞原因

**参考回答：** 记录移除比例、各算子被选率 / 成功率、可行修复率、接受率、当前与最佳成本曲线。若破坏太轻，提高移除规模或引入结构移除；修复过贪，加入 regret 与随机化；接受率过低，重新标定温度；初始解差则改构造法。逐项消融，避免同时改多处无法归因。

**高分要点：** 给出可观测指标与针对性实验，不把“多跑几轮”当通用诊断。

#### 39. 距离增量与时间传播

**题目：** **[增量评估]** 插入客户 $u$ 到 $(i,j)$ 之间时，距离增量为何易于 $O(1)$ 计算，而时间窗可行性可能影响整条后缀？

**考点：** 能否区分距离增量与时间窗后缀传播

**参考回答：** 插入 $u$ 到 $(i,j)$，距离增量只涉及局部三条弧：$c_{iu}+c_{uj}-c_{ij}$。但插入后到达 $j$ 可能推迟，影响后面所有客户；等待时间可以吸收一部分推迟，是否超窗取决于后缀，所以朴素检查是 $O(\text{路线长度})$。

**高分要点：** 非对称成本仍可用此局部距离式；时间窗必须考虑服务时长和后继等待。

#### 40. 用时间缓存加速插入

**题目：** **[时间缓存]** 前向最早服务时间和后向可用 slack 能怎样加快插入评估？哪些边界条件会使所谓 $O(1)$ 检查不正确？

**考点：** 能否正确使用时间缓存和 slack 的边界条件

**参考回答：** 对固定路线预计算前缀最早开始服务 $E_i$ 和后缀允许的最晚开始服务 $L_j$。插入 $u$ 时先算 $B_u=\max(e_u,E_i+s_i+\tau_{iu})$，检查 $B_u\le l_u$ 及 $B_u+s_u+\tau_{uj}\le L_j$，另查容量。若定义正确且弧时间静态，这能常数时间测试单点插入；插入被接受后必须重算受影响缓存。

**高分要点：** 明确 $L_j$ 的含义和仓库截止；多次插入、时变行驶时间、取送货或其他资源可能破坏该判据。

#### 41. 纯 Python 性能热点

**题目：** **[性能]** 纯 Python VRPTW 搜索器的常见热点在哪里？你会先 profile 哪些函数，再决定改数据结构或引入编译组件？

**考点：** 能否通过 profile 定位真实运行热点

**参考回答：** 常见热点是对每个未分配客户枚举所有插入位置、整条路线重复重算、`deepcopy`、Python 对象频繁创建及支配比较。先用 profiler 统计时间和调用次数，再按证据使用局部增量、缓存、紧凑数组、限制候选位置或编译核心循环。

**高分要点：** 先保证验证器和基线正确，再优化热点；用相同实例比较加速倍数与解质量。

#### 42. 距离、路线、访问集的存储

**题目：** **[数据结构]** 距离矩阵、路线序列、访问集合分别适合怎样存储？何时使用列表、NumPy 数组或位集？

**考点：** 能否按访问模式和规模选择数据结构

**参考回答：** 中小规模稠密图可用二维数组存距离 / 时间，随机访问快；大规模候选弧可用稀疏邻接表。路线用连续客户索引列表便于切片与遍历；访问集小规模可用布尔数组或整数位集，位集的包含与交并适合标签支配。选择前应实测访问模式与复制成本。

**高分要点：** 数组、NumPy、Python 列表各有不同解释器 / 内存开销，不宣称某一种永远最快。

#### 43. 时变行驶时间如何改模型

**题目：** **[动态行驶时间]** 若高峰时段行驶时间依出发时刻变化，原来的静态时间递推、标签支配和预处理要怎样改？

**考点：** 能否识别时变行驶时间对递推和支配的影响

**参考回答：** 把 $\tau_{ij}$ 改为依出发时刻的函数 $\tau_{ij}(t)$，转移为 $A_j=B_i+s_i+\tau_{ij}(B_i+s_i)$。标签需保留时刻，删弧与时间下界也按时段计算。若允许在节点自由等待，早到标签可等到晚到标签的出发时刻；若等待受限，或弧成本 / 其他资源依赖出发时刻，原来的支配关系须重新证明。

**高分要点：** 明确可否等待；在不能自由等待时，再检查 FIFO 性质及成本资源是否使“越早越好”成立。

#### 44. 异构车队

**题目：** **[异构车队]** 车辆容量、固定成本和行驶成本不同，主问题和定价如何表示“路线由哪类车执行”？

**考点：** 能否让车型差异进入路线变量与成本

**参考回答：** 路线列扩展为 $(r,k)$，表示由车辆类型 $k$ 执行；列有类型对应的容量、时窗、固定费与弧成本。主问题除客户覆盖外，对每类车加 $\sum_r\lambda_{rk}\le K_k$；定价为每种类型求相应资源受限路线，检验数减客户对偶和该类型车数对偶。

**高分要点：** 若司机、技能或仓库也不同，它们也属于列的资源 / 资格定义。

#### 45. 多仓库 VRP

**题目：** **[多仓库]** 多个仓库时，路线生成、客户覆盖及车队限制如何变化？

**考点：** 能否正确处理多仓库覆盖和车队限制

**参考回答：** 每条路线带出发 / 返回仓库标识，需明确能否跨仓返回；客户仍恰好覆盖一次，各仓库或车辆类型有各自车数约束。定价通常按仓库分别生成路线，成本含对应出发、返回弧及库存 / 车辆限制。

**高分要点：** 先问订单是否预先分仓；若需同时决定分仓与路径，不能把分仓当已知常量。

#### 46. 时间窗越紧意味着什么

**题目：** **[规模分析]** 为什么时间窗收紧可能同时减少可行路线、却也使可行初始解更难找到？

**考点：** 能否解释紧时间窗对搜索的双重影响

**参考回答：** 窗口收紧使许多弧和路线不可行，标签扩展空间可能显著缩小，精确定价有时更快；但可行路线的组合变少，构造初始解及修复更容易失败，可能需要更多车辆。最终难度还受空间分布、车数和需求影响，不能单调断言。

**高分要点：** 分别讨论“搜索状态数”和“寻找可行解”两个方向。

#### 47. MIP start 能做什么

**题目：** **[求解器]** 初始启发式路线怎样作为 MIP start？它可能改善什么，又不能保证改善什么？

**考点：** 能否说明 MIP 启动路线的收益与局限

**参考回答：** 将经过验证的启发式路线映射到 MIP 变量，并作为初始解提交，例如设置变量的 `Start` 值。它可较早给出好 incumbent / 上界，帮助剪枝；但不能保证求解器接受、不能替代模型可行性，也不能自动改善 LP 下界或证明最优。

**高分要点：** 检查变量映射、仓库边重数和所有约束，读取求解器日志确认初解是否被接受。

#### 48. 不同耗时阶段对应措施

**题目：** **[性能定位]** 求解时间主要耗在根 LP、定价、分离、分支树还是 Python 回调时，你分别会采取什么措施？

**考点：** 能否按求解阶段和代码热点制定改进措施

**参考回答：** 根 LP 慢，查模型规模、系数和预处理；定价慢，查标签数、支配、资源界与双向搜索；分离慢，减少冗余割、改候选集合；分支树大，提升下界或初始上界；Python 回调慢，profile 热点并减少跨语言调用。每次只改一类因素并记录前后日志。

**高分要点：** 先定位，再调参数；不能只凭总运行时间判断瓶颈。

#### 49. 公平比较 Solomon 算例

**题目：** **[实验设计]** 如何在 Solomon 算例上公平比较你的 ALNS、OR-Tools 和精确模型，并报告车辆数、距离、可行性、时间与随机波动？

**高分要点：** 若采用不同目标或舍入规则，明确标注“不可直接比较”；SINTEF 的 Solomon 页面也特别提示这些差异。[基准定义](https://www.sintef.no/projectweb/top/vrptw/solomon-benchmark/)

#### 50. 比较 C101 与 C102

**题目：** **[算例对比]** 面对 C101 与 C102 或同系列不同编号实例，你会先比较哪些数据分布，再解释算法表现差异？

**考点：** 能否先比较实例数据再解释性能差异

#### 51. Solomon 基准不一致问题

**题目：** **[基准一致性]** Solomon 距离和时间的计算、舍入、车辆数优先级若与论文不同，为何直接比较目标值可能失真？

**考点：** 能否按一致基准复算车辆数与距离

**参考回答：** Solomon 常见比较采用欧氏距离、时间等于距离、双精度计算，报告时才把总距离保留两位，且先最少车辆再最短距离。若算法用提前四舍五入的整数边权、不同时间语义或单一加权目标，得到的数值不可直接与榜单比较。

**高分要点：** 既报告内部精确目标，也按同一基准规则复算，清楚标注车辆数。[SINTEF 基准说明](https://www.sintef.no/projectweb/top/vrptw/solomon-benchmark/)

#### 52. 加入先后约束

**题目：** **[优先顺序]** 某些客户必须先于另一些客户服务时，紧致模型、标签状态和 ALNS 修复各需改什么？

**考点：** 能否在模型与搜索中正确加入先后规则

**参考回答：** 紧致模型可用服务时刻或顺序变量表达“若两者同车，则 $i$ 先于 $j$”，取送货还需同车约束。标签扩展到 $j$ 前检查其前置客户状态；ALNS 移除 / 插入时可把相关订单成组处理，修复后统一检查先后和同车。

**高分要点：** 单纯写 $B_i\le B_j$ 不足以保证同车，也不能处理客户未服务或不同车的语义。

#### 53. 司机休息与班次

**题目：** **[司机规则]** 加入司机休息、最长连续驾驶时间和班次限制后，标签资源与路线验证器如何扩展？

**考点：** 能否把司机休息与班次加入资源和验证

**参考回答：** 增加自上次休息以来的驾驶时长、总工作时长及班次结束时刻等资源；在可休息位置通过转移重置连续驾驶资源，并把休息耗时计入后续到达。标签支配必须比较新增资源，路线验证器需复放休息安排和终点时刻。

**高分要点：** 区分“行驶时间”和“工作时间”，并确认休息是硬规则还是偏好。

#### 54. 离线最优在线上失效怎么仿真

**题目：** **[仿真]** 静态最优路线在真实运营中表现差，如何用仿真区分需求预测、ETA、路线模型和执行偏差的贡献？

**考点：** 能否区分预测、优化和执行误差来源

**参考回答：** 用历史订单和交通回放：先固定真实订单比较不同 ETA，再固定 ETA 比较不同路径算法，最后加入司机执行和实时插单扰动，逐层分析差距。记录车辆里程、迟到率、改派次数、空驶和拒单，按区域、时段分层。

**高分要点：** 尽可能保持反事实比较的输入一致，避免把数据预测误差误归因给求解器。

#### 55. ETA 误差怎样进入优化

**题目：** **[预测 + 优化]** ETA 模型的预测误差怎样传入时间窗可行性判断？只用平均预测值可能有什么后果？

**考点：** 能否把 ETA 尾部风险纳入可行性判断

**参考回答：** 每条弧使用预测行驶时间及不确定度；可用高分位时间、场景采样或迟到风险罚金评估路线，而非只把均值塞进硬窗。若多段误差相关，应建路线层面的误差传播；最终用真实历史回放校准准时率。

**高分要点：** 预测模型优化 RMSE 与路径决策质量不是同一个指标；要关注尾部迟到风险。

#### 56. 允许拒单的主问题

**题目：** **[未服务订单]** 若允许拒单并支付罚金，主问题如何加入未服务变量？罚金过低会产生什么行为？

**考点：** 能否正确表达拒单及罚金诱导的行为

**参考回答：** 为客户 $i$ 加二元未服务变量 $z_i$，覆盖约束改为 $\sum_r a_{ir}\lambda_r+z_i=1$，目标加 $\sum_i p_i z_i$。若罚金过低，模型会大量拒单；若过高，则数值和运营成本可能受影响，需按收入、服务承诺和容量边际校准。

**高分要点：** 对不可拒客户固定 $z_i=0$；报告拒单数与其客户重要性，不只报告路径距离。

#### 57. 局部事件后的复用

**题目：** **[增量更新]** 一条路线临时取消或交通时间更新后，哪些数据结构和中间结果可以复用，哪些必须重算？

**考点：** 能否管理缓存失效并复用可靠中间结果

**参考回答：** 未变的订单数据、静态距离矩阵和已确认前缀可复用；取消路线或路况变化时，受影响车辆的后缀时间、载重、插入候选与原有成本缓存必须失效重算。若交通矩阵全局更新，不能保留基于旧时间的标签或可行性判定。

**高分要点：** 用版本号或依赖关系控制缓存失效，复用后仍由独立验证器验全局解。

#### 58. SQL 连接后重复订单

**题目：** **[SQL]** 订单表与客户位置表连接后出现重复订单，你会怎样用 SQL 定位一对多连接并验证去重规则？

**考点：** 能否识别一对多连接与可复现去重

**参考回答：** 先检查连接键两侧基数：`GROUP BY customer_id HAVING COUNT(*)>1`，再比较连接前后 `COUNT(*)` 与 `COUNT(DISTINCT order_id)`，定位位置表多版本记录或订单表重复。按时间 / 生效范围挑正确位置版本，例如 `ROW_NUMBER() OVER(PARTITION BY customer_id ORDER BY valid_from DESC)`，而不是不分原因 `DISTINCT`。

**高分要点：** 明确连接键包含租户、日期等业务维度；去重规则应可解释且可复现。

#### 59. pandas 生成实例时如何校验

**题目：** **[Python 数据处理]** 用 pandas 从订单明细生成客户、需求、时间窗及距离矩阵时，如何检查缺失、单位和索引错位？

**考点：** 能否核对缺失值、单位和节点索引

**参考回答：** 建显式 `order_id → 连续节点索引` 映射，固定仓库为 0；校验缺失值、需求和时间单位、窗口顺序、重复 ID，之后生成距离 / 时间矩阵并核对矩阵形状、对角线、非负性和样本行。输出解析后的首尾几位客户与原记录人工交叉核查。

**高分要点：** 不依赖 DataFrame 当前行号作为永久节点 ID；排序、过滤或 merge 后必须重建映射。

## 二、理论与算法题

### 基础与常用原理

#### 60. TSP、CVRP、VRPTW 的关系

**题目：** **[问题定义]** TSP、CVRP、VRPTW 各增加了哪些决策和约束？一个问题何时能退化为另一个？

**考点：** 能否根据车数、容量和时间窗识别问题结构

**参考回答：** TSP 是一辆车访问所有点一次并返回；CVRP 允许多车，要求每条路线载重不超 $Q$；VRPTW 在此基础上要求服务时刻落在客户时间窗内，通常还保留容量。若只有一辆容量足够大的车、时间窗无限宽，VRPTW 可退化到 TSP；容量约束失效且仍多车时是一般 VRP，不自动等于 TSP。

**高分要点：** 明确“退化”还取决于车数、仓库、目标和是否允许漏访。

#### 61. 从零建立标准 CVRP 模型

**题目：** **[现场建模]** 从零建立标准 CVRP 的整数规划模型：定义变量、目标、客户度数、仓库度数和容量约束。

**考点：** 能否完整定义变量、目标和核心可行性约束

**参考回答：** 对无向对称图设客户间 $x_{ij}\in\{0,1\}$，仓库边 $x_{0i}\in\{0,1,2\}$ 以允许 $0-i-0$；最小化 $\sum c_{ij}x_{ij}$。客户度数 $x(\delta(i))=2$，仓库度数 $x(\delta(0))=2m$ 且 $m\le K$；对每个非空客户子集 $S$ 加 $x(\delta(S))\ge2\lceil d(S)/Q\rceil$。这些约束排除不连通或超载的整数路线。

**高分要点：** 讲清单客户路线的仓库重边、$m=K$ 与 $m\le K$ 的区别、GCC 指数多且需动态分离；也可给出自洽的有向流模型。

#### 62. ALNS 完整流程

**题目：** **[ALNS]** 从初始解到终止，完整讲述 ALNS 的破坏、修复、接受、算子选择和最佳解保存流程。

**考点：** 能否完整解释 ALNS 搜索与最佳可行解保存

**参考回答：** 构造初始可行解，保存当前解和最佳可行解。每轮按权重选破坏、修复算子，移除一批客户并重插，计算成本与可行性；用模拟退火等规则决定是否更新当前解，若候选更优且可行则更新最佳解。周期性根据算子表现调权重，到时间或迭代上限返回最佳可行解。

**高分要点：** 分清当前解和最佳解；不可行搜索要有明确罚分与修复策略，最终输出须验证。

#### 63. 破坏与修复算子的分工

**题目：** **[ALNS 算子]** 随机、最差和 Shaw 相关性移除分别在什么情况下有用？贪婪与 regret 插入分别解决什么问题？

**考点：** 能否解释破坏与修复算子的作用和适用情境

**参考回答：** 随机移除增加探索；最差移除优先拆掉边际绕路高的客户；Shaw 移除成组拆掉空间 / 时间相关客户，让重组更有效。贪婪插入每步选最便宜位置；regret 插入优先处理“现在不插，以后选择会明显变差”的客户。

**高分要点：** 提及每个算子可能失败的场景：随机噪声大、最差移除过于集中、相关性权重需归一化、贪婪易把难客户留到最后。

#### 64. 手推 regret-2 插入

**题目：** **[修复算法]** 手推 regret-2 插入：怎样计算最佳与次佳插入代价，如何处理某客户没有可行插入位置？

**考点：** 能否手算插入后悔值并处理无可行位置

**参考回答：** 对每个未分配客户 $u$ 枚举所有可行 `(路线,位置)`，得到两档最小增量 $C_1(u),C_2(u)$，令 $R_2(u)=C_2(u)-C_1(u)$；选最大后悔值客户插入其最佳位置，然后更新受影响的插入成本。若无位置，先尝试可用新车；仍不行则报告修复失败或按已声明的软约束罚分处理。

**高分要点：** 同成本位置的去重 / 次佳路线规则要说明；在车辆数目标优先时增量应是有序指标而非只算距离。

#### 65. 度数为 2 为什么不够

**题目：** **[TSP 建模]** 只有每点度数为 2，为什么求出的可能不是一条完整巡回？举一个子回路例子。

**考点：** 能否用反例识别度数约束留下的子回路

**参考回答：** 度数为 2 只保证选边构成若干个环。例如六个点可形成 $1-2-3-1$ 与 $4-5-6-4$，每点都恰有两条选边，却没有一条巡回经过全部城市。必须加连通性或子回路消除约束。

**高分要点：** 画图并区分无向“度数 2”和有向“入度、出度各 1”。

#### 66. DFJ 两种 SEC 形式

**题目：** **[DFJ]** 写出无向 TSP 的子回路消除约束，并说明内部边形式与割集形式为什么等价。

**考点：** 能否解释 SEC 的两种等价写法

**参考回答：** 对每个非空真子集 $S\subset V$，无向 TSP 要求 $x(\delta(S))\ge2$。由每点度数为 2，求和得 $2x(E(S))+x(\delta(S))=2|S|$，故等价于 $x(E(S))\le|S|-1$。有向图的出割右端为 1，并保持各点入出度为 1。

**高分要点：** 说明约束数量指数级，通常动态分离；全部 SEC 的 LP 仍可能有分数解。

#### 67. MTZ 与 Big-M 松弛

**题目：** **[MTZ]** MTZ 次序变量怎样消除子回路？为什么 Big-M 可能导致 LP 松弛较弱？

**考点：** 能否解释 MTZ 次序和 Big-M 松弛弱点

**参考回答：** 对非仓库节点设置访问序号 $u_i$，如 $1\le u_i\le n-1$、$u_i-u_j+(n-1)x_{ij}\le n-2$。选弧时强制 $u_j\ge u_i+1$，若存在不含仓库环，序号沿环严格递增后回到自身，矛盾。$x_{ij}$ 分数时 Big-M 项大幅放松顺序，根 LP 下界常弱。

**高分要点：** 写出适用的节点范围和 $u$ 界，不把该式直接搬到无向边变量上。

#### 68. 收紧 VRPTW 的 $M_{ij}$

**题目：** **[数值建模]** 对 VRPTW 时间传递约束，如何给每条弧推导尽量紧的 $M_{ij}$，并删除根本不可能使用的弧？

**考点：** 能否从时间窗推导逐弧 Big-M 并安全删弧

**参考回答：** 若 $B_i\in[e_i,l_i]$、$B_j\ge e_j$，时间传递为 $B_j\ge B_i+s_i+\tau_{ij}-M_{ij}(1-x_{ij})$，可取 $M_{ij}=\max\{0,l_i+s_i+\tau_{ij}-e_j\}$，再利用更紧的实际服务时间界改进。若最早离开 $i$ 到 $j$ 的服务开始也超过 $l_j$，弧 $(i,j)$ 可预先删去。

**高分要点：** 不把仓库出发 / 返回误当一个同名时间变量；先确认窗口是开始服务窗及弧可行性，再算 $M$。

#### 69. Lazy constraint 与 user cut

**题目：** **[回调]** TSP 的 lazy constraint 与 user cut 各在何时加入、解决什么问题？若只做整数子回路分离会怎样？

**考点：** 能否区分整数解分离与分数解强化

**参考回答：** TSP 初始只有度数约束时，整数候选若有子回路，必须用 lazy SEC 排除；分数 LP 若违反有效 SEC，可加 user cut 增强下界。只在整数解做连通分量分离仍能保证最终巡回正确，但可能搜索较慢。实现中通常在 `MIPSOL` 检查整数候选，在合适 `MIPNODE` 状态下检查分数解。

**高分要点：** `cbLazy` 的具体可调用位置不限于 `MIPSOL`，但必须保证每个违规整数解都有机会被拒绝，并按 API 设置 `LazyConstraints`。[Gurobi 回调文档](https://docs.gurobi.com/projects/optimizer/en/current/reference/python/model.html)

#### 70. Dijkstra 及其边界

**题目：** **[手写代码]** 实现 Dijkstra 最短路并说明它的适用条件；为什么不能直接用于带负检验数弧的 ESPPRC？

**考点：** 能否说明最短路算法的适用条件

**参考回答：** 用邻接表和最小堆；弹出当前距离最小的点，若堆值已过期则跳过，对每条出弧松弛并入堆。非负边权下复杂度约 $O((|V|+|E|)\log|V|)$。定价的修正弧成本可能为负，且可行性还依赖时间、载重、访问历史，一个节点不能只保留一个最短距离，所以要用资源标签算法。

**高分要点：** 同时讲出负边和多资源两个独立失败原因；负边无负环可考虑 Bellman–Ford，但它仍不能处理 ESPPRC 全部资源。

#### 71. 网格路径数动态规划

**题目：** **[手写代码]** 网格中只能向右或向下，求左上到右下路径数；若部分格子禁止经过，状态转移如何变化？

**考点：** 能否写出网格路径计数的状态与转移

**参考回答：** 设 $dp[i][j]$ 为到该格的路径数；起点为 1，可走格满足 $dp[i][j]=dp[i-1][j]+dp[i][j-1]$，越界当 0。障碍格直接置 0，若起点或终点阻塞则答案 0。时间 $O(mn)$，滚动数组空间 $O(n)$。

**高分要点：** 正确处理第一行 / 列、起终点障碍以及大数是否需取模。

#### 72. 分支定界如何剪枝

**题目：** **[整数规划]** 分支定界如何利用上下界剪枝？初始可行解、强下界和分支变量选择各怎样影响搜索？

**考点：** 能否用有效界解释分支定界的剪枝

**参考回答：** 最小化时，每个节点的松弛值给该子树下界；已有整数可行解给全局上界。节点不可行、下界不优于当前上界、或节点解已整数时可关闭；否则选分数变量分支。好的初解降低 $UB$，强松弛提高 $LB$，两者都能缩小搜索树。

**高分要点：** 下界必须有效；不能把 LP 分数解当成可执行路线，分支策略会影响树的形状。

#### 73. Clarke–Wright 节约法

**题目：** **[构造法]** 推导 Clarke–Wright 节约值；合并路线时为什么必须检查端点、容量和车数？

**考点：** 能否推导节约值并安全合并路线

**参考回答：** 原来两条路线分别含 $0-i-0$、$0-j-0$，连接端点 $i,j$ 后删去 $i-0$ 和 $0-j$，节约 $s_{ij}=c_{i0}+c_{0j}-c_{ij}$。按高节约值尝试合并，但只能连接不同路线的可连接端点，合并后重新验证容量、车数以及有时间窗时的时序。

**高分要点：** 非对称成本要保留方向；正节约不代表合并一定符合业务目标或资源约束。

#### 74. 对称 TSP 的 2-opt

**题目：** **[局部搜索]** 对称 TSP 的 2-opt 如何改变路线？怎样用四条边计算距离增量，什么时候还必须重查时间窗？

**考点：** 能否计算 2-opt 增量并复核资源约束

**参考回答：** 删除 $(a,b)$、$(c,d)$，改连 $(a,c)$、$(b,d)$，中间 $b\ldots c$ 的序列反转。距离增量为 $\Delta=c_{ac}+c_{bd}-c_{ab}-c_{cd}$，$\Delta<0$ 才接受。VRPTW 的反转还会改变行驶方向与各站时刻，不能只凭四条边判断可行。

**高分要点：** 说明该常数增量式依赖对称 TSP；非对称 / 时变问题要重算反转段的内部弧。

#### 75. 常见 VRP 局部算子

**题目：** **[VRP 算子]** Relocate、Swap、Or-opt、2-opt* 分别改变什么结构？跨路线移动后哪些缓存会失效？

**考点：** 能否识别跨路线移动与缓存失效范围

**参考回答：** Relocate 移一个客户，Swap 交换两个客户，Or-opt 移连续片段，2-opt* 交换两车后缀。单车内部移动改变该路线的后续时间；跨车操作同时改变两车需求、时间和成本缓存。所有候选要按路线独立验证，再更新全局目标。

**高分要点：** 分清路线内 2-opt 与跨路线 2-opt*，尤其是带方向和时间窗时后缀不能只比较边成本。

#### 76. 禁忌、退火、ALNS 的不同

**题目：** **[元启发式]** 禁忌搜索、模拟退火、ALNS 的“接受坏解 / 跳出局部最优”机制有何区别？

**考点：** 能否比较不同元启发式跳出局部最优的机制

**参考回答：** 禁忌搜索用短期记忆阻止立刻回退，并可用藐视准则放行特别好的动作；模拟退火按 $e^{-\Delta/T}$ 概率接受劣解，温度逐步下降；ALNS 主要定义大规模破坏与修复邻域，接受机制可使用退火、阈值等。因此 ALNS 与退火并非互斥。

**高分要点：** 三者作用层级不同：邻域生成、接受策略、记忆机制可组合。

#### 77. ALNS 权重更新

**题目：** **[ALNS 自适应]** 怎样根据算子表现更新权重？如何防止一个早期表现好的算子垄断所有迭代？

**考点：** 能否设计 ALNS 算子反馈与探索机制

**参考回答：** 按一段迭代统计每个算子的使用次数和得分，例如刷新全局最好、改善当前解、被接受时给不同奖励；令新权重为旧权重与平均得分的加权组合，再按权重轮盘选择。保留最小选择概率或探索项，避免早期偶然高分让其他算子永远没有机会。

**高分要点：** 得分按调用次数归一化，破坏与修复算子分别管理；性能只在相同预算下比较。

#### 78. Shaw 相关性度量

**题目：** **[Shaw 移除]** 如何定义客户相关性？距离、时间窗、需求各量纲不同，怎样归一化与调参？

**考点：** 能否定义可比较的客户相关性度量

**参考回答：** 可用归一化空间距离、窗口中心 / 重叠、需求差、同路线指示等构造 $R(i,j)$，从种子客户逐步选小 $R$ 的相关客户移除。各项先按数据范围或稳健尺度归一化，权重再用验证实例调参；不能把“公里”直接与“分钟”相加。

**高分要点：** 相关移除的目的在于重组一片可替代客户，不保证每次都改善。

#### 79. 退火温度怎么设

**题目：** **[接受准则]** 模拟退火接受概率中的温度如何初始化和冷却？温度过高或过低有什么迹象？

**考点：** 能否根据接受率和解质量调温度

**参考回答：** 先从若干试探移动估计典型正增量 $\Delta_0$，按期望初始接受率 $p_0$ 设 $T_0=-\Delta_0/\ln p_0$，然后按几何或自适应日程降温。温度太高表现为随机游走、解波动大；太低则几乎拒绝劣解，搜索易停滞。

**高分要点：** 仅对 $\Delta>0$ 用 $e^{-\Delta/T}$，改进解应直接接受；目标尺度变化需重新校温。

#### 80. 三类最短路算法的边界

**题目：** **[最短路]** Bellman–Ford、Dijkstra、标签算法各自处理什么问题？“带负边”与“带资源约束”是同一个难点吗？

**考点：** 能否区分负边与多资源约束两类难点

**参考回答：** Dijkstra 针对非负边权普通最短路；Bellman–Ford 可处理负边并检测可达负环，但仍只优化一个距离状态；ESPPRC 还需时间、载重和已访问客户，多种标签可能同时留在一个节点。因此资源标签 / 动态规划解决的是比“负边”更深的状态维度问题。

**高分要点：** 负检验数不意味着普通图一定存在可重复负环，因为基本路径禁止重复客户。

#### 81. 对偶价格的解释

**题目：** **[LP 对偶]** 线性规划的对偶价格如何解释？在列生成中，为什么一条路线经过高对偶值客户可能更值得加入？

**考点：** 能否解释对偶价格对路线定价的影响

**参考回答：** 在固定当前 LP 基 / 局部敏感范围内，客户覆盖约束右端变化的边际目标变化由 $\pi_i$ 描述。某路线经过对偶价格高的客户，会在 $\bar c_r=c_r-\sum_i\pi_i a_{ir}-\nu$ 中获得更大的扣减，可能成为负检验数列。价格不是客户真实利润，也未必在大范围扰动下保持不变。

**高分要点：** 区分数学影子价格、业务价值和求解器对偶；整数模型本身没有直接同样的线性敏感解释。

#### 82. 除 Big-M 外的模型强化

**题目：** **[模型强化]** 除了收紧 Big-M，你还会怎样利用时间窗删除不可能的弧或增加有效不等式？

**考点：** 能否利用时间窗安全收紧模型

**参考回答：** 预先删除 $e_i+s_i+\tau_{ij}>l_j$ 等不可能连续服务的弧；收紧每点最早 / 最晚可达时刻、载重界，加入容量割、路径不可行割或更强的流表述。所有预处理都要在业务的等待与时间语义下证明安全。

**高分要点：** 不把依赖对称性或三角不等式的删弧规则用于不满足这些条件的实例。

#### 83. 车辆数下界

**题目：** **[车数下界]** 仅根据总需求能给出怎样的车辆数下界？加入时间窗后，还能构造什么更强的必要条件？

**考点：** 能否构造安全的车数必要下界

**参考回答：** 容量立即给 $m\ge\lceil\sum_i d_i/Q\rceil$。时间窗可构造客户不兼容图：若两客户在任何顺序下都无法同车服务，则连一条边；该图中的每个团都要求不同车辆，最大团大小也是下界。还可结合仓库班次和最短往返时间做更强界。

**高分要点：** 不兼容关系必须被证明安全；两个客户看起来相距远，不足以直接断言不能同车。

#### 84. 同质车辆对称性

**题目：** **[对称性]** 同质车辆交换编号会造成怎样的模型对称性？有哪些可行的对称性处理办法？

**考点：** 能否安全处理同质车辆编号对称

**参考回答：** 若车同质，交换车编号不改变实际路线集合，却在三指标模型中生成多个等价整数解，扩大分支树。可用按是否启用排序 $y_1\ge y_2\ge\dots$、或安全的路线排序 / 仓库出发规则打破部分对称性；路线集合划分模型天然减少车编号对称。

**高分要点：** 对称性约束不得排除所有等价最优代表；异质车辆不能随意按编号交换。

### 专项技术追问

#### 85. VRPTW 集合划分主问题

**题目：** **[列生成]** 写出 VRPTW 路线集合划分主问题，并解释为什么容量与时间窗不再显式出现在主问题中。

**考点：** 能否写出路线集合划分主问题的结构

**参考回答：** 令 $\Omega$ 为所有容量和时间窗可行且不重复客户的仓库往返路线，$a_{ir}=1$ 表示路线 $r$ 服务客户 $i$。主问题为 $\min\sum_{r\in\Omega}c_r\lambda_r$，约束 $\sum_r a_{ir}\lambda_r=1\ (i\in N)$、可选 $\sum_r\lambda_r\le K$、$\lambda_r\in\{0,1\}$。容量和时间窗已封装在 $\Omega$ 的定义中。

**高分要点：** 路线数指数多，所以 LP 中只维护 RMP 列集；列生成收敛后仍需整数化。

#### 86. 推导路线检验数

**题目：** **[检验数]** 从主问题对偶变量推导路线检验数；若有“最多 $K$ 辆车”约束，公式还要增加哪一项？

**考点：** 能否从对偶推导正确的路线检验数

**参考回答：** 将 $\lambda_r$ 放松为非负变量；客户覆盖对偶为 $\pi_i$，车辆上限对偶为 $\nu$，则 $\bar c_r=c_r-\sum_i a_{ir}\pi_i-\nu$。每列在车数约束中的系数为 1，所以多出 $-\nu$；若无车数约束，则删掉此项。可在进入客户 $j$ 的弧上减 $\pi_j$，回仓库完成路线时减一次 $\nu$。

**高分要点：** 最小化问题的“$\le K$”对偶 $\nu\le0$；明确客户对偶只扣一次，避免在首尾仓库重复计数。

#### 87. 定价子问题的目标

**题目：** **[定价]** 列生成中定价子问题到底寻找什么？为什么 VRPTW 定价是带资源约束的基本最短路（ESPPRC）？

**考点：** 能否解释定价与资源约束基本路径的关系

**参考回答：** 定价寻找满足单车容量、时间窗、起终仓库和客户不重复约束的路线，使检验数 $c_r-\sum_i a_{ir}\pi_i-\nu$ 最小，若小于 0 就加入 RMP。它是 ESPPRC，因为除最短路成本外还有时间、载重和访问集合资源。

**高分要点：** 解释定价必须足够精确才能宣布“无负列”；负检验数弧不允许直接用普通 Dijkstra。

#### 88. 标签及其扩展

**题目：** **[标签]** VRPTW 标签至少保存哪些状态？从客户 $i$ 到 $j$ 时，成本、时间、载重和访问集合如何更新？

**考点：** 能否正确维护时间、载重、成本和访问状态

**参考回答：** 用 $L=(v,\bar c,t,q,S)$ 表示节点、累计检验数、开始服务时刻、累计需求、已访问客户。扩展 $i\to j$ 时 $\bar c'=\bar c+c_{ij}-\pi_j$，$t'=\max(e_j,t+s_i+\tau_{ij})$，$q'=q+d_j$，$S'=S\cup\{j\}$；若 $j\in S$、$t'>l_j$ 或 $q'>Q$ 就剪枝。

**高分要点：** 说明回仓库的终点窗、司机时长和车辆对偶；若标签时间存的是到达而非服务开始，要相应修改转移式。

#### 89. 标签支配为什么需要访问集

**题目：** **[支配]** 两个到达同一节点的标签，满足什么条件才可安全删除其中一个？为什么访问集合的包含关系不能忽略？

**考点：** 能否给出安全的标签支配条件

**参考回答：** 在同一当前节点，若 $L_1$ 的检验数、开始服务时间、载重均不大于 $L_2$，且 $S_1\subseteq S_2$，在资源单调的标准模型里，$L_1$ 的未来可选客户不少、成本不高，可删去 $L_2$。若忽略访问集，低成本标签可能已经访问了某个未来必需客户，不能模仿另一标签的后续路径。

**高分要点：** 支配只在相同节点和相同其他状态（车辆类型、分支、割状态）下使用；时间可等待是“更早不差”的前提。

#### 90. 基本路径、q-route、ng-route

**题目：** **[路径松弛]** 如果你在项目中使用过路径松弛，基本路径、q-route、ng-route 在速度、下界和可执行性上有什么取舍？

**考点：** 能否说明路径松弛对规模、下界和可执行性的影响

**参考回答：** 基本路径每客户最多访问一次，定价状态需要完整访问历史；q-route 放松重复访问限制，仅按定义累计资源；ng-route 只记局部邻域里的访问点，用较小记忆禁止局部重复。放松后路线集合更大，最小化 LP 下界可能更低，但定价通常更快；松弛列不是最终真实路线。

**高分要点：** 说出 ng 记忆更新 $M'=(M\cap N_j)\cup\{j\}$，并检查扩展前 $j\notin M$；不能声称固定邻域大小总有固定性能收益。

#### 91. 列生成停止说明什么

**题目：** **[最优性]** 没有负检验数列时，列生成证明了什么？为什么还不能直接说原整数问题最优？

**考点：** 能否区分主问题 LP 最优与整数最优

**参考回答：** 在某个分支节点，若精确定价证明所有未生成列检验数 $\ge0$，RMP LP 已等于该节点完整路线模型的 LP 松弛最优值。若 $\lambda$ 分数，仍只得到下界；还需有效割、分支与整数可行上界，才能闭合 Gap。

**高分要点：** 启发式定价“没找到”不等于“证明不存在”，也不保证有效下界。

#### 92. 分支定价怎么分支

**题目：** **[分支定价]** 列生成得到分数路线后如何分支？为什么直接对单个 $\lambda_r$ 分支可能使定价难以延续？

**考点：** 能否说明分支约束如何传回定价

**参考回答：** 从分数路线解恢复原始弧使用量 $x_{ij}=\sum_r a_{ij,r}\lambda_r$，选分数弧做 $x_{ij}=0$ / $x_{ij}=1$ 分支，并让定价遵守节点限制。直接对某一条路线 $\lambda_r$ 分支，另一子节点还可能反复生成大量近似路线，且约束难嵌入最短路定价。

**高分要点：** 强制弧一侧不能只把弧设成很低成本；须用主问题约束、收缩或兼容的定价规则严格执行。

#### 93. CVRP 广义容量割

**题目：** **[容量割]** 对客户集 $S$ 推导 $x(\delta(S))\ge2\lceil d(S)/Q\rceil$；单客户路线对仓库边变量有什么特殊要求？

**考点：** 能否推导容量割及车辆数下界

**参考回答：** 集合 $S$ 的需求 $d(S)$ 至少需 $r(S)=\lceil d(S)/Q\rceil$ 辆车参与，每辆进入再离开贡献 2 次跨割，因此 $x(\delta(S))\ge2r(S)$。若只有一个客户且路线为 $0-i-0$，同一仓库连接被走两次，故无向模型中 $x_{0i}$ 要允许取 2 或使用平行边。

**高分要点：** 说明 $S$ 不含仓库，右端向上取整，而不是 $2d(S)/Q$ 的线性值。

#### 94. 构造违反容量割的分数解

**题目：** **[LP 松弛]** 一个满足度数约束的分数边解为何可能低估真实车数？怎样构造一个违反容量割的例子？

**考点：** 能否用分数解说明容量割强化的必要性

**参考回答：** 取三个单位需求客户、$Q=2$，只允许一辆车的度数模型中令三条客户间边各为 $2/3$，三条仓库边各为 $2/3$。每个客户度数为 $2$、仓库度数为 $2$，但 $S$ 取三个客户时总需求 3，GCC 要求跨割至少 4，现只有 2。它展示基本度数 LP 如何“用一辆分数车”低估所需车辆。

**高分要点：** 把各节点度数和 $x(\delta(S))$ 都算出来；不要把这个例子误说成“满足全部 GCC”。

#### 95. TSP 与 CVRP 割分离

**题目：** **[分离]** TSP 子回路割与 CVRP 容量割的分离难度有何不同？整数解和分数解的分离方法各是什么？

**考点：** 能否区分整数与分数解的割分离

**参考回答：** 整数 TSP 解用连通分量找子回路；分数解以 $x^*$ 作边容量，用全局或多次最小割找容量小于 2 的割。CVRP 整数路线可检查载重并找违规客户集合；分数 GCC 分离的右端含 $\lceil d(S)/Q\rceil$，不是单纯最小割，通常需要专门算法与启发式候选集合。

**高分要点：** 区分“分离一个给定解”与“求原整数问题”；讲清为何不能直接照搬 TSP 最小割。

#### 96. 高级 CVRP 割的作用

**题目：** **[强化割]** 如果你做过 CVRP 分支切割，基本容量割仍不能有效收紧下界时，还会考虑哪些结构？

**考点：** 能否说明高级 CVRP 割要补强的结构

**参考回答：** 基本 GCC 只看某个集合的总需求与边界使用量，仍可能留下涉及多个相交集合、装箱冲突和奇偶拓扑的分数解。Framed capacity、强化梳状和 multistar 等割从这些更复杂的边结构提炼有效不等式，改善根节点下界，但分离代价更高。

**高分要点：** 说清“割必须对所有整数可行路线有效”；若不能准确写某类割的系数，勿现场编公式。

#### 97. 用最小割分离 TSP SEC

**题目：** **[最小割]** 为什么可用最小割寻找违反无向 TSP 子回路约束的分数解？边容量应取什么？

**考点：** 能否把分数边值转成最小割分离问题

**参考回答：** 将当前分数解 $x_e^*$ 作为无向图边容量；求非平凡割 $S$ 的最小 $x^*(\delta(S))$。若值小于 $2-\varepsilon$，该 $S$ 违反 SEC，加入 $x(\delta(S))\ge2$。可用全局最小割，也可通过若干 $s$-$t$ 最小割找到违规集合。

**高分要点：** 不要把原距离 $c_e$ 当割容量；说明数值容差与平凡集合的处理。

#### 98. 梳状不等式

**题目：** **[梳状割]** SEC 都满足时为何仍可能出现分数解？梳状不等式利用了什么集合相交和奇偶结构？

**考点：** 能否解释梳状割针对的分数结构

**参考回答：** 全部 SEC 只保证每个集合至少两次跨越，仍有连通的分数点。梳状结构含梳把 $H$ 和奇数个至少三枚、两两不交且与 $H$ 相交的梳齿 $T_h$；整数巡回满足 $x(\delta(H))+\sum_hx(\delta(T_h))\ge3k+1$。奇偶结构使某些满足 SEC 的分数解被切掉。

**高分要点：** 不能说梳状割切掉全部分数解；能解释“梳齿数为奇数”的重要性。

#### 99. 1-tree 的构造与 TSP 关系

**题目：** **[1-tree]** 什么是 1-tree？它与 TSP 巡回是什么关系，最小 1-tree 如何求？

**考点：** 能否构造最小 1-tree 并解释其下界意义

**参考回答：** 固定根 $r$，在其余节点上取一棵生成树，再让 $r$ 连出两条不同的边，得到 1-tree。每个 TSP 巡回都是所有节点度数为 2 的 1-tree；一般 1-tree 可以有度数为 1、3 等节点，不一定是巡回。最小 1-tree 用一次 MST 加根节点两条最低权边求得。

**高分要点：** 说明 1-tree 是用于下界的较大结构集合，不能把任意 1-tree 当可行 TSP 上界。

#### 100. Held–Karp 型下界

**题目：** **[Held–Karp]** 节点乘子怎样修改 1-tree 边权？它提供的是上界、下界还是一条实际路线？

**考点：** 能否说明节点乘子与 1-tree 下界的关系

**参考回答：** 给节点乘子 $\theta_i$，将边权改为 $c_{ij}+\theta_i+\theta_j$；求最小 1-tree $T$，再减 $2\sum_i\theta_i$，得 $L(\theta)=\min_T[c(T)+\sum_i\theta_i(d_i(T)-2)]$。对乘子取最大得有效下界，因为任何巡回都有 $d_i=2$。最小 1-tree 通常不是实际巡回。

**高分要点：** 若改用列生成对偶 $\pi_i$，指出 $\theta_i=-\pi_i$ 的符号约定；区分下界与启发式巡回上界。

#### 101. LK / LKH 的候选边

**题目：** **[LKH]** LK 与固定 2-opt / 3-opt 的差别是什么？LKH 的候选边和 $\alpha$ 值为何能减少搜索？

**考点：** 能否解释 LK 可变深度交换和候选边用途

**参考回答：** 固定 2-opt、3-opt 只试指定条数的边交换；LK 根据增益动态延长交换链，搜索不同深度。LKH 通过基于 1-tree 灵敏度的 $\alpha$ 值构建候选边集，把注意力放在结构上更有希望的弧，减少无用枚举。

**高分要点：** $\alpha$ 是结构评分，不是最优边出现概率；候选集过窄也可能错过改进。

#### 102. EAX 与普通排列交叉

**题目：** **[遗传搜索]** EAX 如何利用父代边结构产生新巡回？它与简单地交换两个排列片段有何区别？

**考点：** 能否说明 EAX 保留边结构的机制

**参考回答：** EAX 在两条父巡回的边并集中构造交替的 A/B 环，通过替换部分父代边形成子巡回，再修复可能出现的多个子环。它直接保留和重组边结构，而普通排列片段交叉主要保留客户顺序，可能产生重复或缺失城市，需额外修复。

**高分要点：** 说明子代必须仍是一条每点恰好一次的巡回。

#### 103. Giant tour 的 Split

**题目：** **[HGS / Split]** 给一个 giant tour，如何把最优容量可行分段转化为有向无环图最短路？若最多只能用 $K$ 辆车怎么办？

**考点：** 能否把给定客户排列的分段转成最短路

**参考回答：** 将固定客户排列的切分位置设为辅助图节点 $0,\dots,n$；若连续片段 $(i+1,\dots,j)$ 载重可行，则建弧 $i\to j$，弧成本是仓库服务该片段再回仓库的费用。辅助图是 DAG，$0$ 到 $n$ 的最短路给该排列的最优可行分段。限车数 $K$ 时在 DP 状态增加已用车数，或在图上做分层。

**高分要点：** 只对给定排列最优，不能据此宣称求得全局 CVRP 最优。

#### 104. HGS 的多样性与不可行解

**题目：** **[HGS]** 为什么 HGS 既维护解质量也维护种群多样性？暂时不可行解如何避免成为最终输出？

**考点：** 能否同时管理种群质量、多样性和可行性

**参考回答：** 若只保留最低成本个体，种群会趋同，交叉失去意义；因此结合成本和与其他个体的距离评价。搜索中可保留受罚的轻度超载解扩大邻域，另设可行解管理 / 修复，最终只从验证通过的可行解中返回结果。

**高分要点：** 区分搜索评价函数与最终业务目标；罚系数过低会导致持续不可行。

#### 105. RMP 如何初始化

**题目：** **[RMP 初始化]** 如何构造覆盖所有客户的初始列？若单客户路线也不可行，如何检测而不是盲目加大罚值？

**考点：** 能否构造有效初始列并识别不可服务客户

**参考回答：** 常用每客户一条仓库往返路线，只要它本身满足容量、客户窗及仓库 / 司机时限；车辆上限可能使这些列组成的 RMP 不可行，可加入人工变量作 Phase I 并在最终使其归零，或先构造真实多客户路线。若某客户单独服务不可行，先定位原因并检查是否仍能由其他合法路线服务；只有证明任何路线都无法服务时才判原问题不可行，不能靠高罚值掩盖硬约束失败。

**高分要点：** 区分“当前列集不足导致 RMP 不可行”和“完整问题不可行”。

#### 106. 对偶符号和车数项

**题目：** **[对偶]** 覆盖等式与车辆数不等式的对偶变量符号有什么区别？你如何防止定价时漏掉车辆数对偶？

**考点：** 能否核对对偶符号和车辆数项

**参考回答：** 最小化 RMP 中客户覆盖等式的 $\pi_i$ 为自由变量；车数上限 $\sum_r\lambda_r\le K$ 的对偶 $\nu\le0$。列检验数为 $c_r-\sum_i a_{ir}\pi_i-\nu$。用一条已知列在求解器里读出对偶并手算检验数，可核对符号和是否漏掉 $\nu$。

**高分要点：** 车辆上限的对偶符号依具体原始模型 / 求解器约定，最终以 $c_j-\pi^T A_j$ 的列向量公式核查。

#### 107. 一轮加入一列还是多列

**题目：** **[多列定价]** 一轮只加最负检验数路线，与加入多条负检验数路线，各有哪些速度与重复列问题？

**考点：** 能否在多列收益与主问题膨胀间取舍

**参考回答：** 一列使 RMP 小、单轮快，但可能需要很多轮；多列减少定价 / 主问题往返次数，但会增大 LP 和退化风险。可加入若干相异的负检验数路线，去重并限制高度相似列，结合动态阈值控制列池大小。

**高分要点：** 所有加入列都必须资源可行；最终停止仍靠精确定价而非列数上限。

#### 108. 列生成尾效应

**题目：** **[列生成停滞]** 什么是列生成的尾效应？为什么主问题退化和对偶波动会导致许多轮微小改进？

**考点：** 能否诊断退化和对偶波动导致的尾效应

**参考回答：** 接近 LP 最优时，新列往往只带来极小目标改善；主问题退化使大量不同列给出近似相同基解，对偶值可能剧烈波动，导致定价反复产生相似列。可尝试对偶稳定、一次加多列、列管理和更合适的初始列。

**高分要点：** 说明“目标几乎不动”不等于已经证明最优。

#### 109. 对偶稳定化

**题目：** **[对偶稳定]** 列生成中的对偶稳定化大致想限制什么波动？如何确保加速技巧不改变最终正确性？

**考点：** 能否使用稳定化而保留最终精确验证

**参考回答：** 在定价时限制或平滑对偶偏离某个中心，避免 RMP 退化造成的剧烈价格波动，让生成列更稳定。常见思想包括盒约束、惩罚项或中心点更新；这是加速机制。最终仍需用原 RMP 对偶和精确定价检查无负列，保证原问题的 LP 最优性。

**高分要点：** 不把被平滑后的“无负列”直接当标准停止证书。

#### 110. q-route 的重复覆盖

**题目：** **[q-route]** q-route 允许重复客户时，覆盖系数如何定义？为什么这种松弛列不能直接当作可执行路线？

**考点：** 能否解释重复访问列的覆盖系数与限制

**参考回答：** q-route 是定价松弛，可能重复经过客户。若主问题把重复访问计入覆盖约束，系数应按访问次数定义；若采用其他 q-route 松弛构造，也必须保持列系数与其数学定义一致。真实 CVRP 每客户只服务一次，所以重复路线不能直接作为最终方案，必须恢复基本路线或在整数解阶段排除。

**高分要点：** 不能一边允许重复访问、一边默认 $a_{ir}\in\{0,1\}$ 且将其当真实可行路线。

#### 111. ng-route 记忆与效果

**题目：** **[ng-route]** 如果你实现了 ng-route，局部记忆怎样更新？邻域大小会怎样影响速度与下界？

**考点：** 能否推导局部记忆更新及其性能取舍

**参考回答：** 对每个节点 $j$ 定义包含 $j$ 的邻域 $N_j$；标签从 $i$ 到 $j$ 前检查 $j\notin M$，到达后 $M'=(M\cap N_j)\cup\{j\}$。邻域越大，更多旧访问被记住，松弛更接近基本路径，通常下界变强但标签状态和支配成本增加。

**高分要点：** 长环仍可能被遗忘后出现；该路线只能用于松弛下界，最终方案仍需元素性验证。

#### 112. Rank-1 cut 为什么影响定价状态

**题目：** **[割与定价]** 在集合划分 RMP 加 subset-row / rank-1 cut 后，为什么定价可能需要额外状态，而不能总靠简单修改边权？

**考点：** 能否识别新割给定价增加的路径状态

**参考回答：** 主问题新增割后，其对偶给每条路线增加一项与“路线访问了哪些客户、访问组合如何出现”有关的检验数贡献。若这项不能按弧独立相加，只修改固定弧成本就不够，标签需记录相关集合的有限记忆或余数等状态。割越强，可能越难定价。

**高分要点：** 说明选割时要同时考虑下界提升和子问题计算负担；不把所有 rank-1 cut 说成普通线性边成本。

#### 113. 基于弧的分支如何执行

**题目：** **[分支]** 基于弧的分支怎样传入标签定价？禁止弧与强制弧分别如何影响可生成路线？

**考点：** 能否将弧分支约束落实到可生成路线

**参考回答：** 令 $x_{ij}=\sum_r a_{ij,r}\lambda_r$，选分数弧；$x_{ij}=0$ 节点禁止定价生成包含此弧的路线。$x_{ij}=1$ 节点需让主问题恰好选一次该弧，并保证新列遵守该分支条件，可能用兼容的主问题约束、节点状态或收缩技巧实现，而非仅改弧权。

**高分要点：** 每个节点重新做完整列生成；已有列和未来列都要遵守分支。

#### 114. 启发式定价与有效下界

**题目：** **[有效下界]** 若定价只用启发式算法且找不到负列，你能否宣称 LP 最优？若不能，怎样补上精确定价验证？

**考点：** 能否区分启发式定价失败与最优性证明

**参考回答：** 启发式找到了负列就可以安全加入；没找到只说明这次搜索失败，不证明不存在。此时不能把 RMP 目标当完整 LP 最优下界，因为缺失负列可能让真实 LP 更低。若要证明，需运行精确定价或计算能证明最小检验数非负的有效界。

**高分要点：** “加列容易、停止难”是列生成正确性的核心。

#### 115. 加强标签剪枝

**题目：** **[支配强化]** 资源下界、不可达客户集合和访问记忆如何帮助标签剪枝？添加新状态后如何重新检查支配条件？

**考点：** 能否在强化剪枝后重审支配安全性

**参考回答：** 可预先算从当前节点到仓库的最短剩余时间 / 成本下界，若即使理想续接也超窗或不可能改善，则剪枝；记录已不可达客户减少重复尝试，使用 ng 记忆压缩访问状态。支配时，新加的车辆类型、分支、割等状态必须相同或有严格包含关系，否则可能误删有效标签。

**高分要点：** 用可证明安全的资源界做精确定价；启发式候选弧过滤不能伪装成精确剪枝。

#### 116. 双向标签的合并

**题目：** **[双向标签]** 前向和后向标签在中间合并时，如何检查时间、载重、访问集合及检验数的一致性？

**考点：** 能否正确合并双向标签的全部资源

**参考回答：** 前向标签保存从出发仓库到中间点的成本 / 时间 / 载重 / 访问状态；后向标签保存从中间到回仓库的对应资源。合并时核对连接弧、前向完成服务后能赶上后向最晚时刻、合计载重不超 $Q$、访问集除连接点外无重复，并正确合并检验数与割状态。

**高分要点：** 不能只看两边资源各自可行；时间窗、元素性和对偶项在拼接处最易重复计数。

#### 117. Set Partitioning 与 Set Covering

**题目：** **[主问题]** Set Partitioning 的 $=1$ 与 Set Covering 的 $\ge1$ 有何差别？何时不能随意互换？

**考点：** 能否解释集合划分与集合覆盖的语义差别

**参考回答：** $=1$ 要求每位客户恰好被一条选中路线服务；$\ge1$ 只要求至少覆盖一次，可能重复服务。在某些非负成本、满足可安全删去重复客户且不破坏可行性的特殊情形，覆盖模型可等价；有时间窗、取送货、最小订单量等约束时不能默认等价。

**高分要点：** 对偶符号也随约束方向变化；建模前先确认“重复服务”是否允许。

#### 118. Dantzig–Wolfe 分解

**题目：** **[DW 分解]** 从块角结构的原始模型推到 Dantzig–Wolfe 主问题；每个子块的凸组合约束起什么作用？

**考点：** 能否从块角模型推导主问题与凸组合约束

**参考回答：** 原模型有跨子块耦合约束 $\sum_k A_kx_k=b$，各子块满足 $x_k\in P_k$。有界多面体中写 $x_k=\sum_pv_{kp}\lambda_{kp}$、$\sum_p\lambda_{kp}=1$，代入后主问题选择各子块极点列并满足耦合约束；定价在 $P_k$ 中最小化 $c_k^Tx_k-\pi^TA_kx_k-\alpha_k$。

**高分要点：** 指出每个子块各有一个凸组合约束及对偶 $\alpha_k$；VRP 路线列是“单车完整可行方案”的对应物。

#### 119. 局部域无界时为何需要极射线

**题目：** **[分解边界]** Dantzig–Wolfe 推导中，如果局部可行域无界，为什么只用极点可能不够？

**考点：** 能否识别无界局部可行域对分解的影响

**参考回答：** 无界多面体一般表示为极点凸组合加极射线非负组合：$x=\sum_pv_p\lambda_p+\sum_rw_r\mu_r$，其中 $\sum_p\lambda_p=1$、$\mu_r\ge0$。只用极点无法表示沿无界方向延伸的可行点，主问题可能漏掉可行性或目标改进方向。

**高分要点：** 区分有界路线集合与一般 DW 理论；不要对车辆路径问题无故引入不存在的射线。

#### 120. 列生成与 Benders 何时选

**题目：** **[算法选择]** 什么时候用列生成，什么时候用 Benders 分解？分别把哪一部分复杂性移到子问题？

**考点：** 能否根据模型结构选择列生成或 Benders

**参考回答：** 列生成适合变量呈指数多但可通过定价找到有用列的模型，例如完整车辆路线；Benders 适合固定一组主决策后，其余变量形成易求解的子问题，子问题把可行性或目标信息返回主问题形成割。选择看“难点在变量枚举还是约束 / 场景协调”、子问题结构以及整数性。

**高分要点：** Benders 加行、列生成加列，但不能仅靠这句话判断；应给具体 VRP 或网络设计例子。

#### 121. 1-tree 拉格朗日下界

**题目：** **[拉格朗日松弛]** 怎样从 TSP 的度数约束构造 1-tree 拉格朗日下界？乘子和定价对偶之间是什么关系？

**考点：** 能否解释 1-tree 拉格朗日下界的构造

**参考回答：** 把 TSP 的度数等式 $d_i(T)=2$ 以乘子 $\theta_i$ 放入 1-tree 目标，得到 $L(\theta)=\min_T[c(T)+\sum_i\theta_i(d_i(T)-2)]$。任意巡回的罚项为 0，所以 $L(\theta)\le OPT$；最大化 $L$ 得最强此类下界。在列生成记号下，若修正边权写 $c_{ij}-\pi_i-\pi_j$，则 $\theta=-\pi$。

**高分要点：** 说明乘子符号依拉格朗日式约定，不应口头猜正负“代表拥挤”。

#### 122. 行生成与列生成如何结合

**题目：** **[行列生成]** “动态加约束”的分支切割与“动态加变量”的列生成有何对偶关系？两者能否同时使用？

**考点：** 能否说明动态加行与动态加列的关系

**参考回答：** 行生成从少量约束开始，分离被违反的有效不等式并加入；列生成从少量变量开始，定价负检验数列并加入。两者都利用“完整模型太大，只动态处理当前相关部分”的思想。分支切割定价（BCP）在同一搜索树里同时加行、加列，但新增割的对偶必须进入后续定价。

**高分要点：** 每次加割后重新核算检验数，不把旧定价目标沿用到新 RMP。

#### 123. 用网络流找 TSP SEC

**题目：** **[网络流]** 给定一个分数 TSP 边解，你会用哪种最小割 / 最大流工具找违反 SEC 的集合？

**考点：** 能否用最小割找出违反的 TSP 约束

**参考回答：** 以当前 $x_e^*$ 为无向容量，求全局最小割或对多个端点做 $s$-$t$ 最小割；若割值低于 $2-\varepsilon$，输出对应节点子集并加入 SEC。实现可以用 Stoer–Wagner 无向全局最小割或合适的最大流例程，整数解则用 DFS / 并查集更直接。

**高分要点：** 容量是分数边值，不是路程；注意浮点误差与割集去重。

#### 124. 更复杂的 Split

**题目：** **[Split 细节]** 对固定 giant tour，若还要限制车辆数、最大路线时长和软时间窗，Split 动态规划状态与弧权应如何变化？

**考点：** 能否扩展 Split 状态并完整计算路线代价

**参考回答：** 固定 giant tour 后，只为满足容量、最长路线时长等硬约束的连续片段建弧；软窗罚金计入片段最佳服务时刻下的弧权。若限 $K$ 辆，DP 状态为 `(已覆盖位置,已用车辆数)`。若片段成本无法独立于前后片段计算，简单 Split DAG 不再充分，需扩展状态或改用其他解码器。

**高分要点：** 片段弧权必须完整包含仓库往返、服务和迟到罚金，不能只算内部距离。

#### 125. 删除弧与加割的区别

**题目：** **[有效约束]** 预处理删除弧与加入割平面分别改变什么？怎样确认一条删弧规则不会误删最优解？

**考点：** 能否证明删弧规则不会误删可行解

**参考回答：** 安全删除弧改变可选解空间，但需证明任何可行最优路线都不可能用该弧，例如最早到 $i$ 服务后也晚于 $j$ 的最晚服务时间。有效割保留全部整数可行解，只切掉 LP 分数解或当前非法候选。错误删弧会丢掉真正最优解，错误割则可能使模型结论失效。

**高分要点：** 说明删弧证明依赖等待、时间依赖、服务时间与仓库设定。

#### 126. ML 加速与精确性

**题目：** **[ML 加速]** 学习模型若用于排序候选弧或标签，如何测试加速收益？如果直接剪枝，最优性证明受到什么影响？

**考点：** 能否区分学习排序与学习剪枝对证明的影响

**参考回答：** 可以用模型给候选弧、标签或 ALNS 算子排序，减少找到好解 / 负列的时间；用消融实验测时间、质量、最差实例和推理开销。若模型直接永久删掉一部分弧 / 标签，可能漏掉最优路线或负检验数列，精确证明失效，除非再用安全规则或完整定价复核。

**高分要点：** 区分“搜索顺序改变”与“搜索空间删除”，后者需要数学证明或最终精确验证。

#### 127. 稠密图与候选弧稀疏图

**题目：** **[图结构]** 稠密完全图与只保留候选弧的稀疏图分别适合哪些场景？稀疏化怎样影响精确性？

**考点：** 能否说明候选弧稀疏化对精确性的影响

**参考回答：** 中小规模完全图矩阵便于常数时间弧查询；大规模可用邻接表只存候选弧，降低内存和扩展数。若候选弧由启发式筛掉，可能丢掉最优路线，精确算法需要安全删弧证明或最终在完整图上复核。

**高分要点：** 稀疏化效果取决于客户空间结构、时间窗和召回率，不能只看节点数。

#### 128. 标签队列如何选择

**题目：** **[复杂度]** 为标签队列选择堆、双端队列或按资源分桶时，你如何根据扩展顺序与支配成本作取舍？

**考点：** 能否用实际 profile 比较标签队列结构

**参考回答：** 堆可优先处理某个评分低的标签、较早得到负列；双端队列实现简单，适合按固定扩展次序；资源分桶可把相近时间 / 载重标签集中以加速支配。由于检验数弧可能为负，堆顺序不是 Dijkstra 的“出堆即最终最短”证明，精确定价仍需完整安全处理所有未被支配标签。

**高分要点：** 比较时统计队列操作、支配检查和生成标签总数，而非只看堆的渐近复杂度。

#### 129. 位集与 Python `set`

**题目：** **[位运算]** 用位集维护已访问客户，与 Python `set` 相比，在包含判断、复制和支配比较上有何优缺点？

**考点：** 能否比较位集和集合的操作成本

**参考回答：** 位集把客户访问状态压成整数或机器字，交集、并集、包含比较可通过位运算完成，适合客户索引固定的标签；Python `set` 易读、支持动态 ID，但对象和复制开销较大。位集还需考虑节点数很大时多字存储、调试可读性以及不同标签状态的复制频率。

**高分要点：** 给出包含关系测试如 `(A & B)==A`；实际速度通过 profile 证实。

#### 130. 连通分量检测手写题

**题目：** **[手写代码]** 现场给一组无向边和一个整数 TSP 解，写出连通分量检测并返回违反的子集；复杂度是多少？

**考点：** 能否写出连通分量分离及复杂度

**参考回答：** 用选中边建邻接表，遍历每个未访问节点，DFS/BFS 收集一个连通分量；若分量数大于 1，返回所有非平凡真子集作为违反 SEC 的候选。建图 $O(|V|+|E_x|)$，遍历同阶；在整数 TSP 度数为 2 时 $|E_x|=|V|$。

**高分要点：** 变量只按 $i<j$ 存时每条无向边只加入 / 计数一次；不漏掉孤立节点或浮点阈值下的边。
