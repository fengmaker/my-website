# 运筹优化算法工程师面试题库：80 题参考答案

本页与[80 题题库](./运筹优化算法岗面试题库.md)逐题对应。每题保留完整题干，先给出可口述的**参考回答**，再给出面试追问时值得补充的**高分要点**。以下默认最小化问题；涉及求解器的状态、容差和接口时，应以所用版本的官方文档为准。项目经验中的规模、耗时和提升幅度必须替换成自己的真实记录。

## 一、建模与方法选择（1–16）

### 1. 方法、算法与求解器

**题目：** 优化问题的“求解方法”“求解算法”“求解器”分别指什么？举一个排班例子说明三者关系。

**参考回答：** 方法是建模与分解的总体路线，例如把排班写成整数规划或约束规划；算法是具体搜索过程，例如分支定界、动态规划、局部搜索；求解器是实现若干算法并提供建模接口、预处理、日志和状态管理的软件。相同模型可交给不同求解器，同一求解器也可能按模型结构选用不同算法。

**高分要点：** 不把“调用 Gurobi”当成算法说明；交代变量、约束、求解流程和验证办法。

### 2. 精确与启发式的边界

**题目：** 精确算法、启发式算法、元启发式算法的差别是什么？“精确”是否意味着很快？

**参考回答：** 精确算法在适用假设下可给出最优性证明或正确的不可行结论，但最坏时间可能很大。启发式以较低计算代价寻找好解，通常不提供最优性证明；元启发式是可复用的搜索框架，如模拟退火或禁忌搜索，可搭配不同问题的邻域和评价器。

**高分要点：** 区分“找到最优值”和“证明最优”；精确算法在限时停止时也可能只返回可行解与有效界。

### 3. 业务问题如何选法

**题目：** 给定问题规模、时限和质量要求，你如何在专用算法、MIP、CP-SAT、分解与启发式之间选择？

**参考回答：** 先识别结构：网络流、匹配、最短路等可用专用多项式算法；紧凑且松弛较强的线性整数模型先试 MIP；排程中的离散逻辑、互斥和先后关系可试 CP-SAT。变量或约束指数多时考虑列/行生成，严格实时且规模很大时建立可行构造与局部搜索基线。用同一数据和时限比较质量、可行率及稳定性。

**高分要点：** 选法取决于实例结构、证明需求和部署预算，不仅取决于变量个数。

### 4. 从业务语句到模型

**题目：** 接到一个“降低排班成本且满足服务水平”的需求，你会按什么顺序形成可求解模型？

**参考回答：** 明确决策粒度、规划期、输入数据、必须满足的覆盖/劳动规则、可违约规则及其代价，再定义变量、目标和约束。先做能跑通的小模型，手工核对极小实例，再逐步加入复杂规则并建立独立解验证器。

**高分要点：** 先问服务水平是硬下限、期望值还是罚金；确认缺岗、加班与员工偏好是否允许。

### 5. 目标与指标不一致

**题目：** 模型目标值降低了，但业务指标变差，可能是什么原因？如何处理？

**参考回答：** 可能漏掉了业务成本、代理指标与真实指标不一致、目标权重不合理，或离线数据未覆盖执行约束。先拆分目标各项和实际 KPI，找反例并与业务确认优先级；必要时把关键 KPI 改成硬约束或分级目标，再重新验证。

**高分要点：** 例如总工时下降却造成高峰缺岗；报告 Pareto 权衡，而不是只给单个目标值。

### 6. LP、MILP、CP 与 DP

**题目：** 线性规划、混合整数规划、约束规划和动态规划各适合什么结构？

**参考回答：** LP 处理连续线性决策，可借对偶解释资源边际值；MILP 处理离散决策与线性关系；CP 擅长复杂离散可行性和传播；DP 需要可定义状态、转移及可控状态空间。混合使用很常见，例如启发式给 MIP 初始解，DP 为列生成解定价。

**高分要点：** CP-SAT 也能做优化；“适合”不等于对所有实例必然更快。

### 7. 上界、下界和 Gap

**题目：** 最小化问题中可行解、松弛解分别提供什么界？相对 Gap 如何理解？

**参考回答：** 可行解目标值是上界 $UB$，有效松弛或分支搜索给出下界 $LB$，所以 $LB\le OPT\le UB$。常见相对 Gap 用 $(UB-LB)/|UB|$ 表示，但具体分母、零目标和容差按求解器定义核对。只有界足够接近或重合，才有相应精度的最优性证明。

**高分要点：** 下界不能由一个任意“看起来很便宜”的不可行方案充当；最大化时界方向互换。

### 8. 模型强度

**题目：** 两个整数模型可行整数解相同，为什么求解速度可能差很多？

**参考回答：** 两个模型的 LP 松弛可能不同，弱松弛会给出较差的根节点界并增加搜索节点；变量、约束规模、稀疏性、对称性及数值尺度也影响性能。比较根松弛界、节点数和耗时，再决定加有效不等式或换扩展表述。

**高分要点：** “约束越少越快”并不成立，强约束可减少分支；但过多弱割也会拖慢每个节点。

### 9. Big-M

**题目：** 如何推导尽可能紧且有效的 Big-M？M 过大和过小各有什么风险？

**参考回答：** 对激活条件 $z=1\Rightarrow a^\top x\le b$，可写 $a^\top x\le b+M(1-z)$。若变量域已知，可用 $M\ge\max\{a^\top x-b:x\in D\}$ 给出有效上界，并尽量利用其他约束收紧；过小会误删可行解，过大会削弱松弛并带来数值问题。

**高分要点：** 不从业务量纲猜一个天文数字；能用原生指示约束时可测试其性能，但仍需理解变量界。

### 10. 指示约束与逻辑线性化

**题目：** “若开机则满足最小产量”如何建模？指示约束是否总比手写 Big-M 快？

**参考回答：** 设二元变量 $y$ 表示开机，产量 $x$ 的界为 $L y\le x\le U y$，其中 $L>0$ 表示开机最小产量，$U$ 是真实产能上界。原生指示约束也可表达条件逻辑；它有利于避免手工写错，但实际速度依赖求解器变换和模型结构，要用实例比较。

**高分要点：** 如果停机产量必须为零，只有下界 $x\ge Ly$ 还不够，必须有上界或其他约束。

### 11. 对称性

**题目：** 完全相同的机器或车辆为什么会使 MIP 难解？怎样安全破除对称性？

**参考回答：** 交换同质设备编号会得到等价解，求解器可能在等价分支上重复搜索。可按使用顺序约束 $y_1\ge y_2\ge\cdots$，或为同质机器的载荷、首任务设规范顺序；约束必须只删去等价表示，不能删去独有的可行方案。

**高分要点：** 异构成本、资格或班次下不应强行按编号对称化。

### 12. 不可行、无界与未证实

**题目：** 求解器返回不可行、无界、时间到且无可行解，分别意味着什么？

**参考回答：** “不可行”是对当前模型无满足约束解的证明；“无界”表示发现目标可无限改善的方向，但某些求解器的该状态本身不保证已有原始可行解，应按文档核查。时间到且无解只表示截至停止时没找到可行解，不能推出不可行。还要检查模型无效、数值警告以及“不可行或无界”的合并状态。

**高分要点：** 把模型结论与原始业务是否可行分开；模型可能漏约束或数据有误。

### 13. 多目标

**题目：** 字典序目标和加权和目标有什么区别？怎样实现“先满足缺岗最少，再控制成本”？

**参考回答：** 字典序先最小化缺岗数，得到最优值 $s^*$，再在 $s=s^*$ 的条件下最小化成本；加权和 $F s+c$ 仅当 $F$ 足够大且有可证明界时才等价。若业务允许少量缺岗换大幅降本，应明确权衡曲线而不是暗中选择权重。

**高分要点：** 求解器多目标功能通常有优先级及容差设置，必须核对其精确语义。

### 14. 灵敏度与稳健性

**题目：** 输入需求和成本有误差时，你如何判断方案是否稳健？

**参考回答：** 先识别哪些参数不确定、误差范围和分布证据，再做扰动实验，统计可行率、目标波动和关键约束失效位置。若违约代价高，可考虑场景优化、鲁棒约束或滚动重优化；不要把名义解的最优性当作未来场景保证。

**高分要点：** 区分参数敏感性、随机优化与最坏情形鲁棒优化的假设和代价。

### 15. 数据预检

**题目：** 在调用求解器前，你会做哪些数据和逻辑预检？

**参考回答：** 检查主键唯一、缺失值、单位、时间区间、容量与需求的必要条件、上下界顺序、成本尺度和索引映射。再用简单基线或极小实例验证约束方向，输出结构化错误，而不是等求解器返回不可行才排查。

**高分要点：** 必要条件通过不代表整体可行；预检结果要能指向具体订单、资源和规则。

### 16. 公平比较方法

**题目：** 比较 MIP、启发式和 CP-SAT 时，如何设计公平的实验？

**参考回答：** 固定同一批实例、目标与可行性定义、硬件和墙钟预算；统一解验证器，并记录可行率、最优界、目标分布和耗时。随机算法跑多个种子，区分构模/预处理时间与搜索时间，公开超时和失败实例。

**高分要点：** 不把一方“最优性证明耗时”与另一方“找到首解耗时”直接相比。

## 二、精确算法与分解（17–40）

### 17. 单纯形法与基

**题目：** 单纯形法在做什么？为什么一个最优 LP 解还不能直接当整数问题答案？

**参考回答：** 单纯形法在可行基之间移动，借检验数寻找改进方向，直到满足最优性条件；退化时可能目标不变但基改变。LP 松弛允许整数变量取分数值，它的最优值通常只是整数问题的界，不能直接作为可执行方案。

**高分要点：** 说明基可行解与极点的关系，以及退化、多个最优解和数值容差。

### 18. 原始、对偶单纯形与内点法

**题目：** 原始单纯形、对偶单纯形和内点法的起点与适用情境有什么区别？

**参考回答：** 原始单纯形维持原始可行基，对偶单纯形维持对偶可行性并修复原始不可行性；后者常适合约束或界变化后的再优化。内点法沿可行域内部迭代，适合某些大型 LP，但若后续需要基，可能还要 crossover。实际选择由模型和求解器策略决定。

**高分要点：** 不把“内点法一定更快”当定律；关注稀疏性、数值状态和重复求解。

### 19. 对偶价格与检验数

**题目：** LP 的对偶价格和列生成检验数如何解释？为什么符号容易写错？

**参考回答：** 对偶价格反映在局部条件下放宽约束右端对最优值的边际影响；对列 $j$，常见最小化标准形的检验数为 $\bar c_j=c_j-\pi^\top A_j$。不等式方向、变量上下界、最大/最小化与求解器 API 的对偶符号约定都会改变口头公式的解释。

**高分要点：** 先写主问题及其对偶，再推检验数，不靠背公式。

### 20. 全单模与专用算法

**题目：** 为什么某些看似整数的网络流或指派问题不必直接交给通用 MIP？

**参考回答：** 对整数右端且约束矩阵满足全单模条件的 LP，极点可为整数；最短路、最大流、最小费用流和二分图指派还有利用结构的专用算法。通用 MIP 虽能建模，却可能浪费结构优势；加入额外耦合约束后，整数性可能消失。

**高分要点：** 说明“整数右端”和变量界条件，不把所有网络上的问题都称为易解。

### 21. 动态规划的状态

**题目：** 用动态规划求最优解时，怎样判断状态定义充分且没有记录冗余信息？

**参考回答：** 状态要概括未来决策所需的全部历史信息，使同一状态的后续可行集合和代价只依赖当前状态。写出转移、初值和终止条件，再检查状态数、每次转移成本及是否能回溯方案；若两段历史对未来完全等价，可合并。

**高分要点：** 举背包的“已考虑物品与剩余容量”或最短路的“当前节点”说明 Bellman 最优性原理。

### 22. 背包的伪多项式复杂度

**题目：** 0-1 背包的动态规划为什么是伪多项式算法？容量很大时怎么办？

**参考回答：** 按容量做 DP 的时间约为 $O(nW)$，其中 $W$ 是容量数值，而输入表示 $W$ 只需 $O(\log W)$ 位，因此不是按输入位长的多项式时间。容量很大时可考虑按总价值做状态、稀疏状态剪枝、近似方案或 MIP，取决于数值范围与精度要求。

**高分要点：** 说明降维背包为何容量要倒序更新，避免同一物品被重复使用。

### 23. 分支定界

**题目：** 用最小化 MIP 解释分支定界的节点处理和三种常见剪枝。

**参考回答：** 每个节点固定部分变量或添加界，解其松弛以得到该子树下界；若松弛不可行、下界不优于当前上界，或得到满足全部整数性且可行的解，就不再展开该节点。否则选择分数变量分支，并用新可行解更新上界。

**高分要点：** 松弛必须给出有效界；浮点比较要按求解器容差处理。

### 24. 搜索节点与分支变量

**题目：** 深度优先、最佳界优先和强分支各在优化什么？

**参考回答：** 深度优先倾向较快走到叶子并节省开放节点内存，最佳界优先优先改进全局证明；强分支试算候选分支的子节点松弛，挑更有希望改善界的变量，但试算本身耗时。实际求解器常结合伪成本、可靠性分支和启发式。

**高分要点：** “先找到好解”和“尽快证明最优”可能需要不同策略。

### 25. 预处理

**题目：** 求解器预处理通常做什么？为什么不能随意关掉或认为它不会影响调试？

**参考回答：** 预处理可做界收紧、固定变量、删除冗余、替换变量、聚合约束和发现明显不可行。它应保持问题等价或按求解器承诺保持求解正确性，但变换后的模型与原始索引不同，调试回调和数值问题时要看映射；开关预处理应以日志和对照实验为依据。

**高分要点：** 预处理耗时也算总耗时；根节点很久可能是预处理、根 LP 或切割循环。

### 26. 有效不等式

**题目：** 有效不等式和割平面是什么关系？一个“很紧”的约束可能为何无效？

**参考回答：** 有效不等式对所有原问题可行整数解都成立；若它切掉当前分数松弛解，就成为针对该点的割。凭经验添加的约束即使大幅提高下界，若会排除某些合法整数解就是错误模型，而非高质量割。

**高分要点：** 证明有效性、分离违反点、控制割的数目和数值尺度是三个独立问题。

### 27. Gomory 与 MIR

**题目：** Gomory 割和混合整数舍入（MIR）割的共同目的是什么？面试中要避免怎样的过度表述？

**参考回答：** 两者都从线性松弛和整数性出发，构造对整数可行解有效、能排除部分分数解的不等式。它们可增强下界，但不保证加入越多越快；割的稀疏性、系数大小与每轮分离成本同样重要。

**高分要点：** 能手推一个简单舍入例子，例如整数 $x$ 满足 $x\ge 2.3$ 推出 $x\ge3$；别把这种一维示例冒充完整 MIR 推导。

### 28. Lazy constraint 与 user cut

**题目：** Lazy constraint 与 user cut 在语义上有什么区别？什么时候加错会影响正确性？

**参考回答：** Lazy constraint 是原模型必要但延后加入的约束，候选整数解若违反就必须排除；user cut 用来加强松弛，必须对所有原问题可行整数解有效。把必要约束只作为不保证覆盖所有整数候选的普通切割，或加入会切掉合法整数解的 user cut，都可能导致错误结论。

**高分要点：** 回调时机和 API 因求解器不同，应按所用版本文档核对，并验证所有最终解。

### 29. 分支切割

**题目：** 分支切割相对纯分支定界增加了什么？割应只在根节点加吗？

**参考回答：** 分支切割在树搜索中动态分离违反的不等式，以提高节点松弛界、减少搜索。根节点割可全局共享，但深层节点也可能产生有价值的全局或局部割；是否值得加入取决于界提升、割密度和分离耗时。

**高分要点：** 区分全局有效割与只在当前分支约束下有效的局部割。

### 30. 拉格朗日松弛

**题目：** 为什么把难处理的约束移入目标后可以得到下界？乘子如何选择？

**参考回答：** 对最小化问题，把某些约束用符号正确的乘子罚入目标，在较大可行域上求得的拉格朗日函数值对原最优值构成下界；再最大化这个下界以收紧它。通常用次梯度法、束方法或其他对偶优化方式调乘子，并利用松弛后可分解的结构。

**高分要点：** 先写约束方向和乘子符号；松弛子问题的解一般不自动满足原约束。

### 31. 次梯度更新

**题目：** 拉格朗日对偶的次梯度是什么？步长过大或过小会怎样？

**参考回答：** 对偶函数在给定乘子下的次梯度由被松弛约束的违反量构成；沿提升对偶界的方向更新乘子，并投影到允许符号域。步长过大易振荡，过小则收敛慢；需监控对偶界、原始可行解与乘子轨迹。

**高分要点：** 对偶值是界，松弛解需额外修复才能成为上界。

### 32. Dantzig–Wolfe 分解

**题目：** Dantzig–Wolfe 分解为什么会把原变量改写成“列的组合”？

**参考回答：** 若变量可分成若干具有复杂局部可行集的块，块内解可由极点（必要时还包括极射线）表示，主问题选择这些局部方案并满足跨块耦合约束。这样把复杂局部结构藏进列中，但列数可能指数级，需要定价逐步生成。

**高分要点：** 解释耦合约束留在主问题、局部约束进子问题；别把 D-W 与直接放松耦合约束混为一谈。

### 33. 列生成的停止条件

**题目：** 列生成每轮做什么？找不到负检验数列时能证明什么？

**参考回答：** 先解受限主问题得到对偶价格，再在定价子问题中寻找负检验数列并加入，重复迭代。若对完整列空间的定价被精确求解且不存在负列，则当前解对完整主问题的 LP 松弛最优；整数模型仍可能有间隙。

**高分要点：** 启发式定价找不到负列只说明“暂时未找到”，不能作为 LP 最优性证明。

### 34. 列生成的尾效应

**题目：** 列生成后期为何常出现大量轮次却几乎不改善目标？如何处理？

**参考回答：** 受限主问题可能高度退化，对偶价格在等价基之间波动，定价不断产生边际改善很小的列。可尝试对偶稳定化、一次加入多列、过滤重复列或改进初始列，但最终仍要用无偏的精确定价验证停止条件。

**高分要点：** 同时统计主问题时间、定价时间、列数和目标变化，避免只看迭代轮数。

### 35. LP 列与整数可行性

**题目：** 列生成得到了很好的 LP 下界，为什么不能直接把分数列解四舍五入？

**参考回答：** 多条分数列可能共同覆盖同一任务；逐列取整会造成漏覆盖、重覆盖或资源冲突。可用整数主问题、舍入加修复或分支定价找整数可行解；只有经过完整验证的方案才能提供上界。

**高分要点：** 说明下界质量与整数可行解质量是两条不同的进度线。

### 36. Benders 分解

**题目：** Benders 分解怎样在“难离散决策”和“给定决策后的连续子问题”之间分工？

**参考回答：** 主问题选择离散设计变量并用 $\theta$ 估计子问题代价；给定主问题决策后解连续子问题，利用其对偶信息产生最优性割，或在子问题不可行时产生可行性割。不断加入割，直到主问题下界与完整可行方案上界达到停止条件。

**高分要点：** 经典对偶割需要子问题满足相应 LP 强对偶条件；整数子问题不能机械套用同一公式。

### 37. Benders 可行性割

**题目：** Benders 子问题不可行时，为什么不能简单把这次主问题解判为原问题不可行？

**参考回答：** 子问题不可行仅说明当前主问题决策无法扩展为完整方案；其他主问题决策可能可行。应由不可行证据或 Farkas 极射线构造可行性割，排除当前及同类错误决策，然后继续搜索。

**高分要点：** 区分“某个固定设计不可行”和“所有设计都不可行”。

### 38. 行生成与列生成

**题目：** 一个模型同时有指数多的约束和指数多的变量时，你如何理解行生成与列生成？

**参考回答：** 行生成先只放部分约束，发现被当前解违反的约束后加入；列生成先只放部分变量，利用对偶价寻找有利的新列。两者可嵌套或结合，但必须分别保证分离与定价的正确性，并处理二者相互改变对偶和可行域的影响。

**高分要点：** “找不到违反行”和“找不到改进列”的证明条件不同。

### 39. 分支定价

**题目：** 为什么只在根节点列生成后对受限主问题做普通分支，通常不能证明原整数模型最优？

**参考回答：** 根节点只生成了部分列，分支后的子树仍可能需要新的可行列；固定列池会漏掉完整问题中的候选方案。分支定价在每个需要的节点继续解相应定价，并让分支约束传入子问题，才能维护有效界。

**高分要点：** 分支规则要与定价兼容，例如对可解释的弧或任务配对关系分支。

### 40. 正确性证明链

**题目：** 你实现一个自定义精确算法时，怎样向面试官证明它“精确”？

**参考回答：** 说明搜索空间覆盖所有可行解、每个剪枝使用有效界或不可能性证据、定价/分离停止条件经过完整验证，最终可行解通过独立检查。给出上下界闭合或穷尽搜索的终止证明，并用小规模枚举交叉核验实现。

**高分要点：** 经验上总能找到好解不足以证明算法精确；实现中的超时和近似子程序须明确标注。

## 三、启发式与元启发式（41–60）

### 41. 构造、改进与元启发式

**题目：** 构造型启发式、局部改进和元启发式各负责什么？怎样组织一个完整流程？

**参考回答：** 构造型算法快速得到首个可行解；局部改进在定义的邻域里寻找更好解；元启发式管理跳出局部最优、搜索强度和多次重启。常见流程是预检、构造、修复、改进、独立验证，并在限时内保存最佳可行解。

**高分要点：** 每一步都明确可行性和目标语义，不把含罚分的内部解直接当最终方案。

### 42. 贪心何时可靠

**题目：** 如何判断一个贪心规则有最优性保证，还是仅是一条启发式？

**参考回答：** 要证明每步局部选择能扩展成某个全局最优解，常用交换论证、拟阵性质或特殊区间结构；只因直觉上“优先选便宜的”并不足够。若证明条件不成立，就把它作为基线，并用小反例找失败边界。

**高分要点：** 举“按价值密度选物品”对分数背包正确、对 0-1 背包可能失败的反例。

### 43. 初始解质量

**题目：** 初始可行解对局部搜索和精确求解分别有什么价值？

**参考回答：** 对局部搜索，初始解决定搜索起点和可能达到的区域；对最小化的分支定界，好的可行解收紧上界，有利于剪枝。初始解再好也不替代独立验证与下界证明；有时多样化的较差起点能找到更好的最终解。

**高分要点：** 记录首解时间、首解质量及后续改进曲线。

### 44. 邻域设计

**题目：** 设计一个局部搜索邻域时，你会考虑哪些因素？

**参考回答：** 要定义移动操作、候选数量、增量成本、可行性更新及是否能连接有价值的解区域。小邻域便宜但易停在局部最优，大邻域探索更强却可能评估昂贵；可先用交换、插入、块移动等问题相关操作做基线。

**高分要点：** 在排班中，单人换班可能被覆盖约束卡住，可考虑成对交换或多班次链式移动。

### 45. 增量评估

**题目：** 为什么增量评估常比更换一个元启发式框架更能改善运行时间？怎样防止缓存错误？

**参考回答：** 若每次邻域移动都重算全局目标，搜索时间会被重复计算占满；只重算受影响任务、资源和约束可显著增加单位时间的候选数。缓存应有明确依赖和失效范围，定期全量重算并用独立验证器发现漂移。

**高分要点：** 优先 profile，再优化热点；速度改善要包括更新缓存的维护成本。

### 46. 可行搜索与罚函数

**题目：** 搜索过程中允许暂时违反约束有什么好处？最终如何保证输出可行？

**参考回答：** 暂时不可行可穿过可行域中隔开的区域，但需把违反量及尺度明确加入评价函数，并设计修复或自适应罚系数。始终单独保存最佳真实可行解，停止前用独立验证器按硬约束逐项复核。

**高分要点：** 罚分目标更小不等于业务目标更好；硬约束不能因为罚系数有限就变成可交付的软约束。

### 47. 破坏与修复

**题目：** 大邻域搜索为什么常采用“破坏—修复”？破坏比例如何影响搜索？

**参考回答：** 一次移除一批决策可打散局部结构，修复过程重新组合，能跨过单步邻域难以越过的障碍。破坏过小近似普通局部搜索，过大则接近重新构造；比例应结合修复成功率、改进率和单轮耗时调整。

**高分要点：** 修复失败要有明确回退、增大资源或报告不可行的规则。

### 48. 禁忌搜索

**题目：** 禁忌搜索怎样避免在两个解之间反复来回？禁忌期限和特赦规则如何设置？

**参考回答：** 记录最近移动的属性，在若干轮内禁止其逆操作或相同结构，减少短周期回访；若候选解刷新全局最好值，可用特赦规则放行。期限过短易循环，过长会阻挡有价值移动，需要观察重复率和改进曲线。

**高分要点：** 禁忌的通常是移动属性，不必存整个解空间；还要保存最佳可行解。

### 49. 模拟退火

**题目：** 模拟退火如何接受坏解？温度应该怎样初始化和冷却？

**参考回答：** 对成本增加 $\Delta>0$ 的候选，以 $e^{-\Delta/T}$ 的概率接受；温度高时探索强，降低后更偏向改进。可根据代表性劣化幅度与目标初始接受率选 $T_0$，再用冷却曲线和接受率、改进曲线校准。

**高分要点：** 成本尺度变了，温度也须相应调整；固定迭代数与固定时间预算的比较要区分。

### 50. 遗传算法

**题目：** 遗传算法的编码、交叉和变异为什么必须结合问题结构？

**参考回答：** 染色体应能表示候选方案，交叉要保留有价值的结构，变异提供探索；若直接对排列或排班矩阵随意交换，可能产生重复、遗漏或资源冲突。需要设计可行性保持算子或修复器，并用适应度、选择与精英保留控制质量。

**高分要点：** 说明编码到业务解的解码成本，以及早熟收敛和种群多样性问题。

### 51. ALNS

**题目：** 自适应大邻域搜索（ALNS）的算子权重怎样更新？为什么不能只用当前最优算子？

**参考回答：** 每轮选择破坏与修复算子，根据产生全局最优、改善当前解或被接受等表现累计分数，再周期性平滑更新选择权重。单一算子可能只适合搜索某阶段，保留最低选择概率与探索机制能避免过早垄断。

**高分要点：** 区分当前解、历史最佳可行解和候选解；权重更新需按使用次数归一。

### 52. 变邻域搜索

**题目：** 变邻域搜索（VNS）为什么按多个邻域逐层尝试？

**参考回答：** 一个解在某个邻域中局部最优，不一定在另一个邻域中局部最优。VNS 通过切换邻域、扰动与局部下降探索不同结构；改进后可重回较小邻域，使搜索兼顾精细优化和跳出局部盆地。

**高分要点：** 邻域顺序、单轮预算与扰动强度需依数据测试，不是“邻域越多越好”。

### 53. GRASP

**题目：** GRASP 的随机贪婪构造和后续局部搜索各起什么作用？

**参考回答：** 构造时从优质候选的受限列表中随机选择，得到质量尚可且彼此不同的起点；再用局部搜索改进各起点。多次独立迭代后保留最佳可行解，随机化强度控制贪心质量与多样性的权衡。

**高分要点：** 比较其与一次贪心、纯随机重启的差别，并记录每轮构造和改进耗时。

### 54. 迭代局部搜索

**题目：** 迭代局部搜索（ILS）与简单随机重启有什么不同？

**参考回答：** ILS 从已有局部最优解出发施加受控扰动，再进行局部搜索，并用接受准则决定下一轮起点；随机重启通常从头独立构造。ILS 可保留有价值结构，但扰动太弱会回到同一盆地，太强则丢掉已有信息。

**高分要点：** 用重复解比例与盆地间改进率评估扰动是否合适。

### 55. 多样性

**题目：** 种群或解池为何要维护多样性？你会怎样衡量两个方案有多不同？

**参考回答：** 只保留少数相近的高质量解会让搜索集中在一个区域，降低发现更好结构的机会。可按任务分配、边集合、序列位置或资源使用模式定义距离，并在选择或替换时同时考虑质量和差异。

**高分要点：** 多样性度量要与真正有意义的结构相关；过度追求差异会损害解质量。

### 56. 参数调优

**题目：** 模拟退火温度、禁忌期限或 ALNS 破坏比例怎样调，才不容易过拟合算例？

**参考回答：** 将实例按规模和结构划分训练、验证与留出集，用统一预算和多个种子评估可行率、质量分布与耗时。先调影响最大的少数参数，记录搜索轨迹和失败实例；最终在未参与调参的实例上报告结果。

**高分要点：** 避免只公布每个实例中“最佳种子”的成绩。

### 57. 强化与多样化

**题目：** 搜索停滞时，你如何区分应强化当前区域还是转向多样化？

**参考回答：** 若附近仍持续找到小改进，可强化有希望的结构、扩大局部搜索；若重复访问、接受率下降且长时间无改进，可加大扰动、换算子或重启。用最近改进间隔、相似度、可行率和移动接受率判断，而非只凭目标曲线看起来平。

**高分要点：** 停滞也可能是增量评估 bug、罚分设置失衡或时间预算耗在修复上。

### 58. 用求解器做大邻域

**题目：** 怎样把 MIP 求解器嵌入 LNS，而不是让它从零求整个问题？

**参考回答：** 从当前可行解固定大部分决策，只释放一个有意义的子集，交给 MIP 在短时限内重新优化；验证并接受更好方案，再选择新子集。释放范围太小无改善，太大则子问题仍难；可根据热点约束、随机块或冲突区域选变量。

**高分要点：** 明确子问题边界条件，避免局部重新优化破坏全局约束。

### 59. 可复现性

**题目：** 元启发式实验中固定随机种子是否足以保证完全复现？

**参考回答：** 固定种子只是必要条件之一；线程数、遍历顺序、依赖库版本、硬件、浮点求和顺序和时间停止准则也会改变轨迹。应记录代码版本、实例哈希、参数、种子、环境及统一的终止预算，并报告多次运行分布。

**高分要点：** 墙钟限时下的重复运行可能产生不同迭代数，最好同时记录迭代和耗时。

### 60. 启发式解的质量

**题目：** 启发式找到成本 100 的可行解，怎样评价它离最优有多远？

**参考回答：** 若有有效下界 $LB>0$，则真实相对误差 $(100-OPT)/100$ 不超过 $(100-LB)/100$；报告这个可证明的上限时，应说明界的来源和定义。也可与同目标、同预算的基线比较。没有有效下界时只能说相对基线改进，不能声称距最优某个百分比。

**高分要点：** 确保下界与可行解使用同一实例、目标、约束和单位；若目标为零或负值需换合适口径。

## 四、求解器、诊断与落地（61–80）

### 61. 求解器选型

**题目：** Gurobi、OR-Tools CP-SAT、专用网络算法和自写启发式如何分工？

**参考回答：** Gurobi 一类数学规划求解器适合 LP/MIP 等模型及其界和证明；CP-SAT 适合大量整数、布尔逻辑和排程约束；若能落到最短路、流或匹配，专用算法往往更直接；严格限时的大规模复杂实例可用启发式求可行解。选型应在同一实例和模型语义下实测，避免预设“某工具一定更快”。[OR-Tools 选型说明](https://developers.google.com/optimization/mip)

**高分要点：** OR-Tools 是工具套件，CP-SAT 是其中的求解器；接口层与实际后端不能混称。

### 62. CP-SAT 与 MIP

**题目：** 一个带机器互斥、工序先后和最小完工时间的排程问题，为什么值得试 CP-SAT？

**参考回答：** 可把工序表示为时间区间，先后约束连接开始与结束时刻，机器互斥用 NoOverlap 表示；传播能较早排除冲突。MIP 也能表达，但可能引入大量顺序二元变量和 Big-M；两种模型都须用同一时间单位与可行性口径比较。[OR-Tools 排程示例](https://developers.google.com/optimization/scheduling/job_shop)

**高分要点：** CP-SAT 使用整数变量；连续时间需确定离散化精度及其业务误差。

### 63. 读 MIP 日志

**题目：** 读 MIP 日志时，你先看哪几个数来判断“找好解难”还是“证明难”？

**参考回答：** 看 incumbent（当前最好可行解）、best bound（证明界）、Gap、节点数、根松弛和耗时。长时间没有 incumbent 应查可行性与构造启发式；incumbent 已好但 bound 进展慢，应查模型强度、对称性、割和分支策略。[Gurobi MIP 日志](https://docs.gurobi.com/projects/optimizer/en/current/concepts/logging/mip.html)

**高分要点：** 先确认目标方向和多目标/解池模式下列名语义。

### 64. 长时间找不到首解

**题目：** 一个 MIP 两小时没有找到可行解，你按什么顺序排查？

**参考回答：** 先确认状态、日志、数据预检和模型约束方向，再构造小实例或放松部分难约束寻找冲突；能手工构造方案时，给求解器 MIP start 并用独立验证器核对。还可检查 Big-M、对称性和是否把软规则误设为硬约束。

**高分要点：** “没找到解”不等于“不可行”；若已有不可行证明，应转向冲突诊断。

### 65. 下界不涨

**题目：** 已有不错的可行解，但 MIP Gap 长期不降，优先做哪些检查？

**参考回答：** 比较根节点 LP 松弛与最好可行解，判断界是否弱；检查过大的 Big-M、缺失的有效不等式、等价对称解和冗余变量。再看节点处理成本与割效果，尝试更强表述或问题分解，并用相同预算验证是否真的改善。

**高分要点：** 下界增长慢与上界差是不同瓶颈，调启发式力度不一定解决证明问题。

### 66. MIP start

**题目：** 给求解器一个 MIP start 能保证什么？为什么提供的启动解可能被拒绝？

**参考回答：** MIP start 是可行解候选或部分变量建议，求解器会尝试构造/接纳它；它不保证更快，也不保证被使用。索引错位、漏设必要变量、违反约束、数值容差或内部预处理都可能导致拒绝，应检查启动日志与独立验证。[Gurobi Start 属性](https://docs.gurobi.com/projects/optimizer/en/current/reference/attributes/variable.html)

**高分要点：** MIP start 与 LP 的基/原始对偶 warm start 是不同机制。

### 67. 参数调优

**题目：** 调求解器参数时，为什么不建议一上来就把所有 cut 和 heuristic 开到最强？

**参考回答：** 更积极的割和启发式会占用计算时间与内存，可能减少树节点却增加总耗时。先保留默认基线，定位首解、根松弛、节点界还是数值问题，再一次调整少量相关参数，在代表性实例上比较总耗时、解质量与稳定性。[Gurobi 参数建议](https://docs.gurobi.com/projects/optimizer/en/current/concepts/parameters/guidelines.html)

**高分要点：** 记录参数文件与求解器版本，避免只挑单个最快实例汇报。

### 68. 限时与停止条件

**题目：** TimeLimit、Gap、节点上限、找到首解就停，各适合什么业务要求？

**参考回答：** TimeLimit 对应响应时限；Gap 对应证明精度；节点或工作量上限便于控制搜索资源；首解停止只保证可能有可行方案，不保证质量。生产环境可组合硬时间上限与质量阈值，并保留无解、仅有解和已证明最优三种不同结果。

**高分要点：** 停止条件之外还要留数据处理、解码和验证的服务时间。

### 69. 求解状态

**题目：** OPTIMAL、FEASIBLE、INFEASIBLE、UNKNOWN 或 TIME_LIMIT 应如何映射到业务输出？

**参考回答：** 先按具体求解器文档解释状态，再单独检查是否存在可用解、目标值和界。OPTIMAL 是在给定容差内的证明；FEASIBLE 表示有解但未证最优；INFEASIBLE 是模型不可行证明；UNKNOWN 或 TIME_LIMIT 不能直接解释成不可行，可能有解也可能没有。[CP-SAT 状态](https://developers.google.com/optimization/cp/cp_solver)、[Gurobi 状态](https://docs.gurobi.com/projects/optimizer/en/current/reference/numericcodes/statuscodes.html)

**高分要点：** API 返回的状态枚举、解数量与解属性要一起判断，不能盲读空解变量。

### 70. IIS 与可行性放松

**题目：** 模型确实不可行时，IIS 与 feasibility relaxation 分别帮你做什么？

**参考回答：** IIS 找一组本身已不可行、去掉其中任一成员则不再不可行的约束/界，帮助定位冲突，但不保证是业务上最重要或最小规模的冲突。可行性放松按给定惩罚寻找需要放宽哪些约束及放宽多少；它给诊断建议，不能自动改写业务规则。[Gurobi 不可行分析](https://docs.gurobi.com/projects/optimizer/en/current/features/infeasibility.html)

**高分要点：** IIS 可能有多个；松弛罚权需要业务解释。

### 71. 数值尺度

**题目：** 为什么目标系数和约束系数跨很多数量级会带来数值问题？如何处理？

**参考回答：** 浮点计算及求解器容差通常按数值尺度工作，极大系数、极小差值和松弛的 Big-M 会使可行性与界判断不稳定。优先调整单位、推紧变量界和重构模型，再检查系数范围、数值警告与解的残差，而不是只把容差调得更小。[Gurobi 数值指南](https://docs.gurobi.com/projects/optimizer/en/current/concepts/numericguide/tolerances_scaling.html)

**高分要点：** 单位变换要同时作用于目标、约束和业务解释，避免改变问题语义。

### 72. 整数容差与解验证

**题目：** 求解器返回二元变量 0.999999，算不算 1？交付方案怎样保证业务可行？

**参考回答：** 求解器在整数容差内可把它视作 1；解码时按变量类型和容差转成离散决策，再用原始业务数据重新计算覆盖、容量、时间和目标。对接近边界的方案要检查残差和舍入后是否仍可执行，不能只信内部浮点解。

**高分要点：** 不应随意把所有连续变量四舍五入；分别处理整数性、原始约束可行性和业务安全余量。

### 73. Warm start 的区别

**题目：** LP 基 warm start 与 MIP start 有何不同？模型小幅变化后哪个可能更有用？

**参考回答：** LP 基 warm start 提供再优化的基或相关原始/对偶信息；MIP start 提供整数可行方案候选。约束右端小幅变化时，旧 LP 基可能帮助单纯形再优化；新 MIP 可沿用旧业务方案，但必须重新验证可行性。两者作用和 API 不同。[Gurobi 变量属性](https://docs.gurobi.com/projects/optimizer/en/current/reference/attributes/variable.html)

**高分要点：** 旧整数方案在新需求下可能失效；warm start 也可能影响预处理选择。

### 74. 回调

**题目：** 求解器 callback 可以做什么？实现 lazy constraint 或注入启发式解时有哪些风险？

**参考回答：** 回调可读进度、分离割或 lazy constraint、注入候选解和控制停止；不同动作只允许在特定回调位置执行。必须保证割有效、lazy 约束覆盖所有必要候选、注入解可行，并避免回调里做耗时或有共享状态冲突的操作。[Gurobi callback 文档](https://docs.gurobi.com/projects/optimizer/en/current/reference/python/callback.html)

**高分要点：** 并行求解和预处理可能改变回调看到的变量与时机，按具体 API 文档实现。

### 75. 并行与可复现

**题目：** 为什么增加求解器线程数未必线性提速？怎样做可复现的性能比较？

**参考回答：** 多线程会竞争内存带宽、同步搜索状态，也可能改变搜索顺序；实例结构与模型规模决定收益。比较时固定线程数、版本、硬件、参数和种子，记录墙钟时间及求解器提供的工作量指标，并重复运行观察波动。

**高分要点：** 单线程和多线程的“相同节点数”不代表相同耗时；不要把机器资源差异当算法改进。

### 76. 建模接口与后端

**题目：** 用 Pyomo、JuMP 或 OR-Tools 建模后，为什么仍要说明实际调用的后端？

**参考回答：** 建模语言或封装层负责表达模型，实际后端决定算法实现、支持的约束、参数、日志和状态语义。相同上层代码换后端，性能、数值容差或功能可能不同；实验报告应记录后端名称与版本、模型规模和关键参数。

**高分要点：** 不能把“使用某建模库”直接等同于“使用某求解算法”。

### 77. 独立验证器

**题目：** 为什么已有求解器可行性检查，还要自己写业务解验证器？

**参考回答：** 求解器检查的是所提交模型在其容差内可行，无法发现遗漏的业务规则、数据映射错误或解码错误。独立验证器用原始输入重算目标与每条硬约束，给出可定位的错误，并在启发式、MIP、CP-SAT 的输出上复用。

**高分要点：** 对边界值、空资源、重复分配和索引错位设计极小反例。

### 78. 基准测试

**题目：** 新方法在公开实例上快了 20%，你还需要核对什么才能对外宣称改进？

**参考回答：** 核对目标、约束、数据版本、硬件、线程、时限和预处理是否一致；若是随机方法，报告多种子均值、分位数和失败率。还要给每类实例的逐项结果、可行性验证和总计算时间，不只报挑出的最佳平均值。

**高分要点：** 若只减少求解时间却增加建模或数据处理时间，线上收益可能不存在。

### 79. 临场排程建模

**题目：** 给 20 台机器、200 道工序、工序先后、换型时间和交期，如何先搭一个可运行基线？

**参考回答：** 先确认工序是否可选机器、加工时间、换型是否依前后顺序、交期罚金与加班边界。用区间/先后与机器互斥建一个小规模 CP-SAT 模型，或用顺序二元变量建 MIP；逐步加入换型、延期和资源规则，验证完整模型输出，再与满足全部硬约束的简单派工基线比较。

**高分要点：** 如果换型时间依序列，单纯 NoOverlap 不足以表达全部换型逻辑，需额外状态、顺序或转移建模。

### 80. 上线后效果落差

**题目：** 离线算例表现很好，上线后却经常超时或违反实际规则，你会怎样复盘？

**参考回答：** 分开核对输入分布变化、业务规则遗漏、模型/数据版本、求解时间分布、接口延迟、解码验证和人工执行偏差。保留每次实例、日志、参数与输出，重放失败案例；再针对真正瓶颈改模型、启发式或系统集成，并设置超时可行回退方案。

**高分要点：** 报告可行率、迟到/违约、成本和端到端响应时间，而不只看求解器目标值。
