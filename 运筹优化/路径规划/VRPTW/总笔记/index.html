    ALNS VRPTW 精确算法

    VRPTW 总笔记：时间窗模型、列生成、标签算法与 ALNS¶

    整合本文件夹的发展路线、模型建立、dw 分解、精确算法、研究方案和路线。精确算法与 ALNS 是两条互补的求解路线：前者可给出下界与最优性证明，后者侧重在计算预算内寻找高质量可行解。

    阅读指南与相关方法¶

    本专题按“概述 → 数学模型 → 算法专题 → 实现计划”阅读。算法演进综述、精确算法学习路线和开发方案分别承担不同用途。

    1. 问题与模型：时间窗模型、算法演进综述。
    2. 精确求解：先读列生成与 DW 原理，再读路径模型与 DW 分解、分支定价与标签算法。精确算法学习路线按练习顺序串起这些概念。
    3. 启发式路线：通用方法索引、本页 ALNS 小节。
    4. 实现计划：纯 Python / ALNS 开发方案在项目板块收录；学习与职业路线在资料库收录。
    5. 个人实现与实测：VRPTW Solver已完成 M0～M12，附四求解器对照、结果表与输出示例；原 ALNS 设计稿与当前 ILS 实现分别说明。

    1. 问题定义与时间递推¶

    设仓库为 0，客户集为 \(N\)。客户 \(i\) 有需求 \(d_i\)、服务时长 \(s_i\)、开始服务时间窗 \([e_i,l_i]\)；弧 \((i,j)\) 有行驶成本 \(c_{ij}\) 和行驶时间 \(\tau_{ij}\)。一辆车容量为 \(Q\)，可选设最多 \(K\) 辆车。每位客户恰好服务一次，每条路线从仓库出发并返回，载重不超 \(Q\)，所有服务开始时间落在对应时间窗内。仓库也可能有出发和返回时间限制。

    对路线中连续节点 \(i\to j\)，若 \(A_j\) 为到达时间、\(B_j\) 为开始服务时间，则

    \[A_j=B_i+s_i+\tau_{ij},\qquad B_j=\max\{A_j,e_j\},\qquad B_j\le l_j.\]

    早到允许等待 \(B_j-A_j\)；行驶成本 \(c_{ij}\) 与行驶时间 \(\tau_{ij}\) 要分开保存，不能在无说明时互换。目标可能是先最小化车辆数，再最小化总距离，也可能是最小化固定车队下的总成本。建模、求解和比较算例时必须先统一目标。

    2. 精确算法的模型演进¶

    阶段 决策对象 处理时间窗的方法 瓶颈 / 作用
    紧致模型 车辆弧 \(x_{ijk}\)、服务时刻 Big-M 时间传递 容易实现基线，LP 松弛可能弱
    分支切割 弧与动态有效不等式 容量割、路径可行性割等 时间是累积资源，分离不简单
    路线集合划分 完整可行路线 \(r\) 在路线生成时检查 列数指数多，需要定价
    分支定价 / BCP 路线、分支、有效割 标签算法处理资源 可形成精确证明，但工程复杂

    2.1 紧致模型为什么常遇到困难¶

    三指标模型中，\(x_{ijk}=1\) 表示车 \(k\) 从 \(i\) 到 \(j\)；服务时刻 \(B_{ik}\) 可通过

    \[B_{jk}\ge B_{ik}+s_i+\tau_{ij}-M_{ij}(1-x_{ijk})\]

    连接。\(M_{ij}\) 应由时间窗推紧，并分别处理仓库出发和返回节点。若 \(M_{ij}\) 过大，分数 \(x_{ijk}\) 会使时间传递几乎失效，根节点下界偏弱。可先删除时间上不可能的弧、收紧 \(M_{ij}\)，并将此模型作为小实例基线；不能仅凭某个节点数断言它必然解不动。

    2.2 路线主问题¶

    令 \(\Omega\) 为所有容量及时间窗可行、客户不重复的仓库到仓库路线。\(c_r\) 是路线成本，\(a_{ir}\in\{0,1\}\) 表示路线 \(r\) 是否服务客户 \(i\)，\(\lambda_r\) 表示是否选用路线。集合划分主问题为

    \[\begin{aligned} \min\quad&\sum_{r\in\Omega}c_r\lambda_r\\ \text{s.t.}\quad&\sum_{r\in\Omega}a_{ir}\lambda_r=1\quad(i\in N),\\ &\sum_{r\in\Omega}\lambda_r\le K\quad\text{（若有车辆上限）},\\ &\lambda_r\in\{0,1\}. \end{aligned}\]

    主问题负责覆盖和车数；每列自身负责容量、时间窗和回仓库可行性。若目标首先最小化车数，则应使用分级优化，或有严格上界依据的权重，不能随意将两层目标混成一个未校准的成本。

    2.3 Dantzig–Wolfe 分解与列生成¶

    dw 分解中的一般形式把各车辆 / 子块的局部可行域 \(P_k\) 表示为极点的凸组合，再让主问题协调客户覆盖等耦合约束。若 \(P_k\) 有极射线，还需包含射线项；对有界的路线选择集合，可以只考虑极点。VRPTW 的路线集合划分正是这种“完整局部方案作为列”的具体视角。

    由于 \(\Omega\) 无法全部列出，先取一部分路线 \(\Omega'\)，松弛 \(\lambda\) 后求限制主问题（RMP）。设客户覆盖约束对偶为 \(\pi_i\)，车辆上限约束对偶为 \(\nu\)，则新路线的检验数为

    \[\bar c_r=c_r-\sum_{i\in N}a_{ir}\pi_i-\nu.\]

    没有车辆上限约束时去掉 \(\nu\)。对一条不重复客户的路线，可把客户对偶放在进入客户 \(j\) 的弧上：\(\tilde c_{ij}=c_{ij}-\pi_j\)，并在完整路线结束时减去一次 \(\nu\)；也可放在离开客户 \(i\) 的弧上，二者一致，但代码只能选一种以免漏算或重复扣减。最小化问题中，定价找到 \(\bar c_r<0\) 的可行路线就加入 RMP；只有精确检查确认所有未生成路线都没有负检验数，才可宣布该节点的完整 LP 松弛已收敛。随后仍可能需要分支才能得到整数最优解。

    3. 定价子问题：ESPPRC 与标签算法¶

    定价是在修正成本下寻找从仓库到仓库的基本路径（客户不重复），同时满足容量和时间窗，即带资源约束的基本最短路问题（ESPPRC）。修正边权可能为负，普通 Dijkstra 的非负边权假设不适用。

    一个前向标签可写为 \(L=(v,\bar c,t,q,S)\)：当前节点 \(v\)、累计检验数 \(\bar c\)、当前开始服务时间 \(t\)、累计载重 \(q\)、已访问客户集 \(S\)。从 \(i\) 扩展到未访问客户 \(j\)：

    \[\begin{aligned} \bar c'&=\bar c+c_{ij}-\pi_j,\\ t'&=\max\{e_j,t+s_i+\tau_{ij}\},\\ q'&=q+d_j,\\ S'&=S\cup\{j\}. \end{aligned}\]

    若 \(t'>l_j\) 或 \(q'>Q\)，立即丢弃；扩展回仓库时还须检查其返回时间窗 / 路线时长，并扣除车辆数对偶 \(\nu\)。若 \(t\) 存储“到达时间”而非“开始服务时间”，递推公式也应相应改变，不能把两种状态混用。

    3.1 优势准则¶

    同一节点 \(v\) 上，若两个标签 \(L_1,L_2\) 满足

    \[\bar c_1\le\bar c_2,\quad t_1\le t_2,\quad q_1\le q_2,\quad S_1\subseteq S_2,\]

    则在标准资源单调条件下，\(L_1\) 可支配 \(L_2\)：它当前更便宜、更早、更空，而且禁止继续访问的客户不更多。比较的成本必须是检验数，而不是原始距离。实际实现还要处理车辆类型、路程界、割状态等额外资源；这些资源加入后，支配条件也要同步扩展。

    3.2 ng-route、双向标签与割¶

    完整访问集合 \(S\) 可能造成状态爆炸。ng-route 仅记录与当前节点邻域相关的部分访问历史，因此允许部分长距离重复访问，用更便宜的定价计算一个松弛下界。此类重复路线不能直接当作真实可执行解，最终整数方案要恢复并验证基本路径属性。

    双向标签分别从仓库出发与向仓库回溯，在满足时间、容量、访问记忆和割状态兼容条件时合并；它减少单向扩展深度，但并非简单把运行时间“减半”。subset-row / rank-1 cuts 能增强主问题下界，其对偶影响可能需要在标签中加入有限记忆状态，不能一般性地只改一次弧成本。分支规则也须传给定价，使生成的新列遵守当前分支节点的限制。

    4. 启发式路线：纯 Python ALNS 求解器¶

    研究方案提出借鉴 PyVRP 的数据 / 解 / 搜索分层，自己实现纯 Python ALNS。可保留 Model、ProblemData、Route、Solution 之类的概念，但接口应按项目实际支持范围设计；参考 PyVRP 公开 API 不等于实现与其完全兼容。

    4.1 数据与可行性¶

    • ProblemData 存距离矩阵、时间矩阵、需求、服务时长、时间窗和车队参数；读入 Solomon 等算例后核对仓库、客户数、单位及舍入规则。
    • Route 保存客户序列，并能从仓库依次重算载重、到达 / 开始服务 / 等待 / 返回时间和成本。
    • Solution 汇总路线，检查所有客户恰好出现一次、车数约束及每条路线可行。初期用完整遍历保证正确，再优化局部增量评估。

    4.2 ALNS 循环与算子¶

    1. 用贪婪插入或其他构造法产生初始可行解，分别维护当前解与历史最佳可行解。
    2. 破坏：随机移除增加多样性；最差移除针对高边际成本客户；Shaw 相关性移除按距离、时间窗、需求等相似性成组移除；后续可加入连续片段移除。
    3. 修复：贪婪插入选最小增量位置；regret-\(k\) 插入优先处理“错过当前最佳位置代价大”的客户。每次插入都检查容量、时间窗和车数；若暂时允许不可行解，须明确定义罚分与最终修复步骤。
    4. 接受与自适应：可用模拟退火或记录阈值接受部分较差解，按算子的近期贡献调整选择权重。达到时间或迭代预算后返回历史最佳可行解。

    对插入位置 \((i,j)\) 尝试客户 \(u\) 时，距离增量为 \(c_{iu}+c_{uj}-c_{ij}\)。时间窗影响可能传播到后继节点；先用整条路线重算校验，再在有测试覆盖后引入前向最早时间、后向最晚时间或 slack 摘要。只有在明确缓存定义与边界条件后，才可声称某种插入检查是 \(O(1)\)。

    5. 一条可执行的学习与开发顺序¶

    顺序 产出 应检查的结果
    1 数据读取与路线验证器 等待、迟到、超载、回仓库、漏访和重复访问样例
    2 小实例紧致模型 与验证器使用同一目标和时间定义
    3 集合划分 RMP + 小规模枚举定价 对偶、检验数、列加入与 LP 停止条件
    4 标签定价与支配 与枚举定价在小实例上的最小检验数一致
    5 分支 / 割（如需精确证明） 整数解可行，且上下界闭合时才报告最优
    6 贪婪构造 + ALNS 相同预算和随机种子下的可行解成本、车数与耗时

    阅读路径可沿原精确算法中列出的 Gilmore–Gomory 列生成入门、Feillet 等人的 ESPPRC 标签算法、Baldacci 等人的 ng-route，以及 Pessoa 等人的通用 VRP 精确求解框架。项目实践应分别报告启发式上界和精确算法下界；如果用启发式规则直接删除定价标签，得到的“下界”未必仍有效，必须重新用精确定价验证。

    原路线还提出从精确算法、工业启发式延伸到机器学习辅助搜索。可把学习模型用于候选弧排序、标签扩展顺序或 ALNS 算子选择，并以关闭 / 开启学习模块的消融实验评估收益。若学习模型直接剪掉可能包含负检验数的路径，列生成的精确终止判据就失效；需要在证明最优前恢复完整定价。将求解器、算例读取器、可行性验证器和实验脚本整理为独立模块，比只报告一个目标值更能说明实现的可靠性。
